## 1. 설계 원칙

**대전제: 자산의 가격은 많은 정보를 선반영하여 내포하고 있다.**

이를 알고리즘용으로 구체화하면 다음과 같다.

1. 가격이 오르는 데는 이유가 있고, 그 이유를 먼저 아는 참여자가 먼저 산다. 따라서 이유를 몰라도 **가격 움직임 자체가 이유의 흔적**이다.
2. 다만 정보는 즉시 완전히 반영되지 않는다. 정보를 가진 참여자는 나눠서 사기 때문에 **이유 있는 상승은 지속적**이다(과소반응 → 추세).
3. 이유 없는 상승(테마, 수급 이벤트, 숏커버링)은 단발적이고 되돌려진다(과잉반응 → 반전). 한국 시장은 개별 종목 반전 경향이 강하다.
4. 그러므로 전략의 핵심 과제는 **"이유 있는 상승"과 "이유 없는 상승"을 시장 데이터만으로 구분**하는 것이다.

"이유 있는 상승"을 판별하는 세 가지 증거를 사용한다.

| 증거 | 의미 | 측정 |
|---|---|---|
| 추세 (가격) | 시장이 꾸준히 위로 재평가 중 | 이동평균 위치·기울기, 채널 돌파 |
| 거래량 | 새 정보가 들어오며 참여자가 늘어남 | 돌파일 거래량 / 평균 거래량 |
| 수급 주체 | 정보 우위 가능성이 큰 주체가 매수 중 | 외국인·기관 순매수 |

입력 데이터는 **시장에서 생성되는 데이터(OHLCV, 지수, 투자자별 매매)로 한정**한다. 재무지표는 신호로 쓰지 않는다.

## 2. 전략 구조 (4개 레이어)

```
[유니버스] → [L1 시장 국면] → [L2 종목 추세] → [L3 진입 트리거] → [L4 순위·비중]
                                                         ↓
                                                  [청산 규칙 (매일)]
```

> v04부터 L3·L4를 대체하는 **스코어링 모드(2-5, C 계열)**를 병행한다. 유니버스·L1·비중 산정·거래비용·벤치마크는 공유하고, 진입·순위·청산만 다르다.

### 2-0. 유니버스

- Trading Universe의 한국 주식. 가능하면 **시점 기준 KOSPI 200 구성종목**(생존편향 방지)
- 유동성 필터: 20일 평균 거래대금 하한 (예: 100억 원, 파라미터)
- 관리종목·거래정지 종목 제외

### 2-1. L1 시장 국면 필터 (매주 점검)

- **Risk-on**: KOSPI 종가 > 60일 이동평균 **그리고** 60일선이 5거래일 전보다 높음
- **Risk-off**: 위 조건 불충족 → 신규 진입 금지, 기존 포지션은 청산 규칙대로만 관리
- 근거: 이동평균 전략의 마켓타이밍 능력(국내 논문), 2022년 하락장 회피

### 2-2. L2 종목 추세 필터 (매일 계산)

아래를 모두 만족하는 종목만 후보:

- 종가 > 60일 이동평균 (최근 분기 매수자 대부분이 수익 중)
- 60일선 기울기 > 0 (5거래일 전 대비) = 60일 전 대비 가격 상승
- 20일선 > 60일선 (단기 추세가 중기 추세보다 강함)

### 2-3. L3 진입 트리거 (매일 점검, 다음 날 시가 체결)

**가격 조건 (필수)**
- 종가 > 직전 20거래일 최고가 (Donchian 20 돌파)

**거래량 확인 (실험 변수 V)**
- 돌파일 거래량 ≥ 20일 평균 거래량 × 1.5

**수급 확인 (실험 변수 F)**
- 최근 20일 (외국인 + 기관) 누적 순매수 > 0
- 최근 5일 (외국인 + 기관) 누적 순매수 > 0
- 비교 가능하도록 정규화: `수급강도 = 순매수대금 / 20일 평균 거래대금`

### 2-4. L4 순위와 비중 (매주 조정)

후보가 보유 가능 종목 수보다 많을 때의 순위 점수:

```
점수 = 순위(20일 수급강도) + 순위(60일 상대강도)
상대강도 = 종목 60일 수익률 − KOSPI 60일 수익률
```

- 최대 보유 종목 수: 5~8 (단일 종목 상한 20% → 최소 5종목이면 완전 투자 가능)
- 비중: 변동성 기반. 종목당 위험 = 평가액의 1% / (2 × ATR20), **상한 20%**
- 정수 주 단위 매수 (시드 1,000만 원이라 고가주는 상한 미만으로 담길 수 있음)
- 섹터 상한 검토 (예: 동일 업종 40%) — 반도체 동시 편입 시 사실상 단일 종목화 방지

### 2-5. 스코어링 모드 — "추세 + 눌림" (C 계열, v04 신규)

**아이디어**: 다섯 지표는 모두 "과거 N일 대비 현재 가격 위치"를 기간만 달리 잰 값이다. 한국 시장은 **긴 기간은 추세 지속, 짧은 기간은 반전**이 우세하므로(8장 참고), 긴 지표는 (+), 짧은 지표는 (−)로 써서 **"추세는 강한데 최근 며칠 쉬어간 종목"**을 고른다.

**(1) 지표 정의 (매일, 종가 기준)**

| 지표 | 정의 | 시간 척도 | 역할 | 부호 |
|---|---|---|---|---|
| MA50Div | 종가 / MA50 − 1 | 중기 | 추세 방향 | + |
| Range52 | (종가 − 252일 최저가) / (252일 최고가 − 252일 최저가), 0~1 | 장기 | 추세 위치 | + |
| MA20Div | 종가 / MA20 − 1 | 단기 | 과열 판정 | 게이트(상단 제외) |
| R10 | 종가 / 10거래일 전 종가 − 1 | 단기 | 단기 반전 | − (가중 0.5) |
| R3 | 종가 / 3거래일 전 종가 − 1 | 초단기 | 진입 타이밍 | − |

- **변동성 정규화 (기본 적용)**: R3, R10, MA20Div는 종목의 `ATR20 / 종가`(ATR%)로 나눈다. 같은 +5%도 저변동 종목에서는 의미 있는 움직임, 고변동 종목에서는 노이즈이므로 신호 대 잡음비로 비교한다. (C2에서 정규화 없는 버전과 비교)
- Range52의 대안으로 기존 `high52_prox`(종가 / 252일 최고가, George & Hwang 방식)를 C3에서 비교한다.

**(2) 1단계 — 게이트 (통과/탈락, 매일 계산)**

아래를 모두 만족해야 점수 대상이 된다. 합산 점수에서 생기는 **보상 효과**(추세가 약한데 급락해서 "눌림"으로 오인되는 종목)를 막기 위해 추세 판단은 점수가 아니라 게이트로 한다.

- 유동성 충족 (2-0)
- MA50Div > 0 (종가가 50일선 위)
- Range52 ≥ 0.70 (52주 범위 상단 30% 이내)
- **과열 제외**: MA20Div(정규화 값)가 유동성 충족 종목 중 상위 5% 이내면 제외

**(3) 2단계 — 점수 (게이트 통과 종목 대상)**

각 지표를 매일 **유동성 충족 종목 전체에서 퍼센타일 순위(0~1)**로 변환한 뒤:

```
추세점수   = pct(MA50Div) + pct(Range52)                 # 0 ~ 2
타이밍점수 = −pct(R3) − 0.5 × pct(R10)                   # −1.5 ~ 0
총점       = 추세점수 + 타이밍점수
총점순위   = 총점의 퍼센타일 (게이트 통과 종목 내, 0~1)
```

- 원값 대신 순위를 쓰는 이유: 지표마다 단위·분포가 달라 원값 합산 시 R3처럼 변동이 큰 지표가 점수를 지배하고, 이상치에도 약하다.
- 가중치는 **1 : 1 : 1 : 0.5 고정**. 부호는 6-1-2 IC 분석 결과로만 바꾸며 가중치 최적화는 하지 않는다(6-5).

**(4) 매수 (주간 점검일, 다음 날 시가 체결)**

- L1 Risk-on **그리고** 게이트 통과 **그리고** 총점순위 ≥ 0.80
- 빈 슬롯 수만큼 총점 높은 순으로 매수 (최대 보유 종목 수·비중 산정은 2-4와 동일: 1% 위험 / (2 × ATR20), 상한 20%, 정수 주)

**(5) 매도**

- **상대 기준 (주간 점검일)**: 보유 종목이 게이트는 통과했지만 총점순위 < 0.50이면 매도.
  매수 문턱(0.80)과 매도 문턱(0.50)을 다르게 두는 **히스테리시스** — 순위가 경계에서 떨릴 때마다 매매하는 것을 막는다(왕복 비용 약 0.43%, 4-1).
- **절대 기준 (매일)**: 아래 중 하나라도 발생하면 순위와 무관하게 매도
  1. MA50Div < 0 (종가가 50일선 아래 — 추세 게이트 이탈)
  2. 초기 손절: 종가 < 진입가 − 2 × ATR20 (3장과 동일)
- **Donchian 10 이탈 청산(3-1)은 C 계열에서 사용하지 않는다.** 눌림 매수는 정의상 단기 저점 부근에서 사므로, 10일 저가 이탈 규칙이 진입 직후 청산을 유발한다.
- 과열 게이트(MA20Div 상위 5%)에 걸린 보유 종목은 **매도하지 않는다** (과열은 신규 진입만 막는 조건).

**(6) 파라미터 (config 제안)**

```python
# 2-5 scoring mode (C-series)
score_ma_long: int = 50            # MA50Div
score_ma_short: int = 20           # MA20Div
score_r_short: int = 3             # R3
score_r_mid: int = 10              # R10
score_r_mid_weight: float = 0.5
score_range_window: int = 252      # Range52
gate_range_min: float = 0.70
gate_overheat_pct: float = 0.95    # MA20Div percentile above this -> no new entry
score_buy_pct: float = 0.80        # buy threshold (percentile within gated names)
score_sell_pct: float = 0.50       # weekly relative sell threshold (hysteresis)
score_vol_normalize: bool = True   # divide R3, R10, MA20Div by ATR20 / close
score_range_mode: str = "range"    # "range" | "high52_prox"
```

## 3. 청산 규칙 (매일 점검, 다음 날 시가 체결)

> A·B 계열 기준. C 계열(스코어링)의 청산은 2-5 (5) 참고.

아래 중 하나라도 발생하면 전량 청산:

1. **추세 이탈**: 종가 < 직전 10거래일 최저가 (Donchian 10)
2. **초기 손절**: 종가 < 진입가 − 2 × ATR20
3. **수급 이탈 (실험 변수 FX)**: 최근 10일 (외국인 + 기관) 누적 순매도 **그리고** 종가 < 20일선

청산은 리밸런싱 주기와 무관하게 **매일** 점검한다. (10일 이탈을 주 1회 점검하면 최대 4거래일 지연 발생)

## 4. 운용 가정 (기존 확정 사항)

- 매년 첫 거래일 1,000만 원으로 시작, 마지막 거래일 종가로 평가
- 1,000만 원 초과분은 연말 균등 매도해 현금화
- 단일 종목 상한 20%
- 거래비용: 4-1 거래비용 모델 적용 (전략·벤치마크 동일)

### 4-1. 거래비용 모델

**원칙**
- 모든 비용은 **설정값(config)으로 분리**하고 코드에 하드코딩하지 않는다.
- 세율은 **체결일 기준 연도별 테이블**로 적용한다 (백테스트 기간 중 세율이 여러 번 바뀜).
- 전략과 벤치마크(BM1~BM3)에 **동일한 비용 모델**을 적용한다.
- 비용은 체결 금액 기준으로 계산해 현금에서 차감하고, 거래별·연도별로 기록한다.

**(1) 증권거래세 — 매도 시에만 부과 (농어촌특별세 포함)**

| 적용 연도 | KOSPI (거래세 + 농특세) | KOSDAQ |
|---|---|---|
| 2021~2022 | 0.08% + 0.15% = **0.23%** | 0.23% |
| 2023 | 0.05% + 0.15% = **0.20%** | 0.20% |
| 2024 | 0.03% + 0.15% = **0.18%** | 0.18% |
| 2025 | 0.00% + 0.15% = **0.15%** | 0.15% |
| 2026~ | 0.05% + 0.15% = **0.20%** | 0.20% |

- 구현 전 국세청·KRX 공지로 테이블 재확인 (향후 세법 개정 시 행 추가)
- **ETF(KODEX 200 등) 매도는 증권거래세 면제** → BM1·BM3에는 거래세 0

**(2) 매매 수수료 — 매수·매도 모두 부과**
- 기본값: 편도 **0.015%** (온라인 수수료 + 유관기관 제비용 가정)
- 실제 사용 증권사 요율로 교체 가능하도록 설정값 처리
- 최소 수수료가 있는 경우 옵션으로 반영 (시드 1,000만 원·소액 주문에서 영향 가능)

**(3) 슬리피지 — 매수·매도 모두 부과**
- 체결 가정: 신호 다음 날 **시가** 체결
- 기본값: 편도 **0.10%** (시가 단일가 체결의 괴리 + 호가 스프레드 가정)
- 유동성 연동 옵션: 주문금액 / 20일 평균 거래대금 비율이 클수록 슬리피지 가산
- 체결가는 **호가단위(tick size)로 반올림** — 매수는 올림, 매도는 내림 (불리한 방향)
- 상한가 시가 매수 / 하한가 시가 매도는 **미체결 처리** 옵션 (다음 날 재시도)

**(4) ETF 비용 (벤치마크 BM1·BM3)**
- 매매 수수료 + 슬리피지(대형 ETF 기준 편도 0.02% 수준 가정)
- 총보수: 연율을 일할로 NAV에서 차감 (수정주가에 이미 반영된 경우 이중 차감 금지)

**(5) 세금 (참고, 기본 비활성)**
- 배당소득세 15.4%: BM1(TR)과 전략 보유 종목 배당에 동일 적용 여부를 옵션으로
- 국내 상장주식 양도소득세: 대주주 요건 미해당 가정으로 미적용

**비용 가정 요약 (기본값, 편도 기준)**

| 항목 | 매수 | 매도 |
|---|---|---|
| 수수료 | 0.015% | 0.015% |
| 슬리피지 | 0.10% | 0.10% |
| 증권거래세 | – | 연도별 0.15~0.23% |
| **왕복 합계 (2026 기준)** | | **약 0.43%** |

→ 왕복 0.4% 수준이면 연 20회전 시 비용만 연 약 8%. **회전율 관리가 수익률만큼 중요**하다.

**비용 민감도 분석 (필수)**
- 비용 0배(무비용) / 1배(기본) / 2배(보수적) 세 시나리오로 동일 백테스트
- 무비용 대비 1배에서 성과가 크게 무너지면 → 진입·청산 빈도 조정 필요 신호
- 리포트 항목: 연간 총 비용(원·%), 비용 항목별 분해(수수료/세금/슬리피지), 회전율, 비용 차감 전후 Sharpe

**구현 인터페이스 (제안)**

```python
@dataclass(frozen=True)
class CostModel:
    commission_rate: float = 0.00015          # 편도
    slippage_rate: float = 0.0010             # 편도
    min_commission: float = 0.0
    tax_table: dict[int, dict[str, float]]    # {연도: {"KOSPI": 0.0020, "KOSDAQ": 0.0020, "ETF": 0.0}}
    round_to_tick: bool = True
    block_limit_up_down: bool = True
    cost_multiplier: float = 1.0              # 민감도 분석용 (0 / 1 / 2)

    def buy_cost(self, trade_date, market, price, qty) -> TradeCost: ...
    def sell_cost(self, trade_date, market, price, qty) -> TradeCost: ...
```

- `TradeCost`는 수수료·세금·슬리피지를 분리해 반환 → 리포트에서 항목별 집계
- 호가단위 테이블도 연도별 설정값으로 분리 (2023년 호가단위 개편 반영)

## 6. 검증 계획

### 6-1. 선행 검증 (전략 구현 전)

#### 6-1-1. 이벤트 스터디 (A 계열)

전제 자체를 먼저 확인한다. 모든 Donchian 20 돌파 이벤트를 모아 조건별로 이후 5·20·60일 수익률을 비교:

- 거래량 확인 있음 vs 없음
- 외국인+기관 순매수 vs 순매도 상태에서의 돌파
- 개인 단독 순매수로 인한 돌파

→ 차이가 없으면 해당 필터는 전략에서 제외. **"이유 있는 상승을 수급·거래량이 구분해주는가"를 데이터로 먼저 확인**하는 단계.

#### 6-1-2. 팩터 IC·5분위 분석 (C 계열, v04)

점수를 조합하기 전에 **각 지표가 예측력이 있는지, 부호가 가설과 맞는지** 먼저 확인한다.

1. **상관행렬**: 5개 지표(정규화 전·후)의 횡단면 순위 상관 평균. |ρ| > 0.8인 쌍은 하나로 합치거나 하나를 제외 (특히 R10 ↔ MA20Div 예상)
2. **Rank IC**: 매일 지표 순위와 이후 5·10·20일 수익률(t+1 시가 기준) 순위의 상관 → 평균 IC, IC 표준편차, IC IR(평균/표준편차), IC > 0 비율
3. **구간별 IC**: 2021~22 / 2023~24 / 2025~26 각각 — 부호가 뒤집히는 지표 확인
4. **5분위 분석**: 총점 기준 5분위 포트폴리오의 이후 수익률이 1→5분위로 **단조 증가**하는지, 5분위 − 1분위 스프레드

**가설 부호와 판정 규칙**

| 지표 | 가설 부호 | IC가 가설과 반대이고 구간 3개 중 2개 이상에서 일관되면 |
|---|---|---|
| MA50Div | + | 게이트·점수에서 제외 검토 |
| Range52 | + | `high52_prox`로 교체 검토 |
| MA20Div | 상단 과열 시 − | 과열 게이트 제거 |
| R10 | − | 부호 반전 또는 제외 |
| R3 | − | 부호 반전 (눌림 가설 기각 → 모멘텀 타이밍으로 전환) |

- 판정 결과로 **부호만** 바꾸고 가중치는 바꾸지 않는다. 변경 시 다음 버전으로 기록한다.

### 6-3. 벤치마크

각 벤치마크는 서로 다른 질문에 답한다. 하나만 쓰지 않는다.

|---|---|---|---|
| BM1 | **KOSPI 200 총수익(TR)** — 기본 벤치마크 | 지수를 그냥 보유했으면? | KOSPI 200 TR 지수 또는 KODEX 200 수정주가 (배당 포함 필수) |

**가장 중요한 것은 BM3.** 전략이 BM3을 위험조정 기준으로 이기지 못하면 복잡도를 더할 이유가 없다.

**공정 비교 규칙**
- 벤치마크도 전략과 **동일한 운용 가정**(4장)을 적용: 매년 첫 거래일 1,000만 원 매수, 마지막 거래일 종가 평가, 초과분 현금화
- 거래비용 동일 적용 (ETF는 매매비용 + 총보수)
- 가격지수 사용 금지 — 배당 누락으로 벤치마크가 매년 배당수익률만큼 불리해짐
- 현금 보유분은 BM4 금리로 이자 발생 처리 (전략·BM3 동일)

### 6-4. 평가 지표

**절대 지표 (전략·벤치마크 공통 산출)**
- CAGR, 연간 수익률, 변동성 (모두 **비용 차감 후** 기준)
- Sharpe (BM4 차감, 목표 ≥ 1.5)
- MDD (목표 ≤ 15%), Calmar = CAGR / |MDD|
- 회전율, 승률, 평균 보유기간, 거래비용 합계, 평균 현금 비중

**벤치마크 대비 지표 (BM1 기준, 필요 시 BM3 기준 병기)**

| 지표 | 정의 | 보는 것 |
|---|---|---|
| 초과수익 | 전략 수익률 − 벤치마크 수익률 | 얼마나 이겼나 |
| 정보비율(IR) | 초과수익 평균 / 초과수익 표준편차 (연율화) | 얼마나 꾸준히 이겼나 |
| 베타, 알파 | 일별 수익률 회귀 (전략 = α + β·벤치마크) | 시장 추종분과 전략 고유분 |
| 상승 포착률 | 벤치마크 상승 월의 전략 평균 / 벤치마크 평균 | 오를 때 얼마나 따라가나 |
| 하락 포착률 | 벤치마크 하락 월의 전략 평균 / 벤치마크 평균 | 빠질 때 얼마나 덜 빠지나 |
| 구간별 승패 | 2021~22 (하락) / 2023~24 (박스권) / 2025~26 (상승) 각각 | 국면별 강약점 |

**판정 기준 (추세추종이 설계대로 작동했는가)**
- 기대 모양: 상승 포착률 60~80%, 하락 포착률 30~50%
- 강한 상승장(예: 2025년)에서 BM1에 지는 것은 정상 — 현금 비중·종목 상한·진입 지연 때문
- 목표는 "매년 지수를 이긴다"가 아니라 **"하락 구간에서 지키고, 전체 기간 위험조정수익(Sharpe·Calmar)에서 BM1·BM3을 이긴다"**

**강건성**
- 주간 점검 요일(월~금) 변경 시 성과 분산
- 파라미터 주변값(예: 돌파 15/20/25일)에서 성과가 급변하지 않는지

### 6-5. 과최적화 방지

- 파라미터는 소수 후보만 비교 (이동평균 20/60/120, 돌파 20/55 등)
- 최적값을 세밀하게 찾지 않는다
- 가능하면 마지막 1년은 홀드아웃으로 남겨 최종 확인에만 사용

### 9-2. 구현 결정과 스펙 대비 차이 (다음 버전에서 재검토)

- **유니버스**: 시점 기준 KOSPI 200 구성종목 이력은 사용 가능한 소스가 없어 **현재 시가총액 상위 N(기본 200)** 을 쓴다. 생존편향이 있으며 리포트 경고에 명시한다. 관리종목·거래정지 제외는 유동성 하한(20일 평균 거래대금)으로만 근사한다. **빌드 시점 시가총액 상위 유니버스(look-ahead 포함)를 알려진 한계로 수용한다 — 2026-10-14 사용자 결정(NEX-14 질문 카드).** 리포트 머리말 경고는 유지한다(코드 변경 없음).
- **연말 리셋**: 마지막 거래일 **종가**로 초과분을 보유 종목에 비례해 매도(정수 주)하고 현금을 인출한다(t+1 체결 규칙의 유일한 예외 — 새해 첫 거래일이 정확히 1,000만 원으로 시작하게 하기 위함). 부족분은 1,000만 원까지 입금 처리한다. NAV는 연간 결과를 체인으로 이어 붙여 하나의 곡선으로 지표를 계산한다.
- **L4 "매주 조정"** (2026-10-14 개정, NEX-19 — NEX-14 사용자 결정 "C5 단일 종목 20% 상한: 상시 한도"): 진입 수량은 1% 위험 / (2 × ATR20)와 20% 상한 중 작은 값(정수 주)이고, 상한은 두 곳에서 상시 적용한다. (a) **체결 시**: t+1 시가 체결에서 수량을 `floor(0.20 × 체결 직전 평가액 / 체결가)`(체결가 = 시가 + 호가 반올림, 이미 보유한 수량은 차감) 이하로 자른다 — 갭 상승으로 시가가 신호일 종가보다 높아도 체결 직후 비중이 20%를 넘지 않는다(체결 직전 평가액 기준; 수수료로 줄어든 평가액 대비로는 0.0x%p 넘을 수 있다). (b) **주간 초과분 매도**: 주간 점검일 종가 기준 비중이 20%를 넘는 보유 종목은 `보유수량 − floor(0.20 × 평가액 / 종가)`주를 다음 세션 시가에 매도한다(사유 `weight_trim`). **줄이기만 하고 늘리지 않으며** 20% 이하 종목은 매매하지 않는다. A0~A5와 B 모두, L1 Risk-off 주에도 적용하고 BM1~BM4는 적용하지 않는다(`Order.weight_cap`은 `TrendFollowingPolicy`의 매수만 설정). 부분 매도라 거래 통계(`metrics.trade_stats`)에서는 연말 트림처럼 제외한다. 파라미터(20%, 1%, ATR20, 보유 수)는 그대로다. 이전(v03 구현)에는 비중을 진입 시점에만 정하고 재조정이 없어 V1 측정에서 체결 시 최대 20.62%, 보유 중 최대 32.6%까지 올랐다. 순위 점수는 후보가 빈 슬롯보다 많은 날에만 적용한다. **섹터 상한은 미구현**(업종 데이터 없음).
- **B 변형**: 주간 점검일에 L2 통과·유동성 충족 종목을 52주 고가 근접도(종가 / 252일 최고가)로 정렬해 상위 `max_positions`를 동일 비중(≤ 20%)으로 보유, 순위 밖 종목은 매도. 3장의 일별 청산(Donchian 10·ATR 손절)은 그대로 적용.
- **수급 데이터**: KIS `inquire-investor`는 최근 약 30일만 주므로 백테스트용 이력은 **Naver frgn 페이지**(수량)로 수집하고 당일 종가를 곱해 금액화한다. 기관 세부 주체(연기금·투신 등) 구분은 이 소스에 없어 5장의 주체별 비교 실험은 미구현. 수급이 없으면 A3~A5는 건너뛰고 리포트에 경고한다.
- **BM1/BM3 데이터**: **KODEX 200TR(278530)** 가격을 사용한다(분배금 재투자형이라 가격 자체가 총수익, 총보수는 가격에 반영 → 이중 차감 없음). 없으면 KODEX 200(069500)으로 대체하고 "가격지수" 경고를 낸다.

### 9-4. Trading Universe 주간 추천 — 2-5 스코어링 활용 (2026-09-29)

Trading Universe 탭의 **Trend Score** 버튼이 표의 KOSPI/KOSDAQ 행(지수·금리·원자재 행과 미국 종목 제외)을

버튼은 고정 중 checked 상태이고 다시 누르면 기본 순서로 돌아간다. 전체 갱신 후에도 고정은 유지된다(다시 누를 때까지).
처음(2026-09-29 1차)에는 점수·게이트·지표를 담은 별도 다이얼로그(`ui/dialogs/trend_score.py`)였으나 사용자 지시로 표 내 고정으로 바꾸고 다이얼로그는 삭제했다
(git `20d5360` 이전). 백테스트가 아니라 현재 시점의 신호 목록이며, 다음 결정은 2-5 본문에 없는 것이다.

- **유니버스**: 2-0의 KOSPI 200 구성종목이 아니라 **Trading Universe 표에 있는 종목 전체**(KOSPI + KOSDAQ, 사용자 추가분 포함).
  유동성 하한(20일 평균 거래대금 ≥ `min_avg_trading_value`, 기본 100억)은 그대로 적용되어 미달 종목은 퍼센타일·점수 계산에서 빠진다.
- **데이터 창**: Universe 갱신이 쓰는 `data.cache.start_date()`(410일 전)와 같은 시작일로 `data.history`를 조회하므로 전체 갱신 직후에는
  네트워크 호출 없이 `_HIST_CACHE`에서 읽는다. 달력은 KOSPI(`KS11`) 거래일. Range52는 `signals.high52_prox`와 같이 252일 창의 80%(201일)
  이상 이력이 있으면 계산한다(상장 10개월 이상).
- **"지난 1주일" 점수**: 매일의 총점(유동성 종목 내 퍼센타일 합, −1.5~+2)을 **최근 5거래일(`score_week_sessions`) 평균**한 값이다.
  일별 총점이 이미 횡단면 정규화돼 있어 날짜 간 평균이 가능하다. 최근 세션에 점수가 있고 5일 중 3일(`score_week_min_sessions`) 이상
  채점된 종목만 대상이다.

  상태 라벨에 "KOSPI L1 Risk-on/off"로 표시만 한다(Risk-off이면 신규 진입 금지가 스펙). 총점순위(게이트 통과 종목 내 퍼센타일)와 매수 문턱 0.80은
  표에 노출하지 않는다(`ScoredName.latest_rank`에는 있다).

### 9-6. V1 보완 (NEX-16, 2026-10-14)

NEX-14 감사의 보완 요청 중 사용자 결정이 필요 없는 항목. 전략 규칙·파라미터는 바뀌지 않았다(스펙 2-0의 "한국 주식"·"거래정지 제외"를 코드가 따르도록 맞춘 것).

- **ETF/ETN 제외 (2-0)**: Naver/FDR 목록 행에는 Code·Name·Marcap뿐이라 `dataset.is_etf_name`이 **이름**으로 판별한다(운용사 브랜드 접두어 `KODEX·TIGER·RISE·ACE·SOL·PLUS·TIME·HANARO·KBSTAR·…` + 공백, 또는 `ETN` 토큰). `data/`는 건드리지 않았다. `load_dataset`은 `universe_size × 2`행을 받아 ETF/ETN을 빼고 위에서 `universe_size`개 주식을 채운다(`select_stock_universe`). 이전 스냅샷의 193종목 중 37개가 이 규칙에 걸리며 V1이 센 37개와 같다. 한계: 이름 규칙이라 새 브랜드는 목록에 추가해야 하고, 맥쿼리인프라 같은 인프라펀드·리츠는 주식처럼 상장돼 있어 유니버스에 남는다. BM1·BM3의 ETF 비용 처리(`CostModel.for_etf`)는 그대로다.
- **거래량 0 세션 (2-0 "거래정지 제외")**: 시가 > 0이어도 그 세션 거래량이 0이면 엔진이 매수·매도 모두 체결하지 않고 다음 세션에 재시도하며(매수는 `max_order_retries`, 매도는 무제한), `Features.traded`가 False인 날은 신규 진입 후보(A·B 모두)에서 뺀다. 거래량 NaN(봉 없음)은 `traded`를 막지 않는다(다른 필터가 이미 실패시킨다). 연말 트림은 종가 기준이라 영향이 없다.
- **상장폐지 vs 거래정지 (B2·G3)**: 두 경로는 별개다. 상장폐지 청산(`delisted`)은 **종가가 없는**(결측) 세션이 `delist_after_missing`(10)번 이어질 때만 발동하고 마지막 종가를 호가단위로 내려 매도가로 쓴다. 가격은 있고 거래량만 0인 정지 행은 결측 카운터를 올리지 않으므로 아무리 길어도 `delisted`가 되지 않으며, 그동안 주문만 체결되지 않고 이월된다.
- **리포트 머리말 영향 수치 (B1)**: `Dataset.info`에 `ended_in_window`(평가 종료일 10세션 이상 전에 데이터가 끝난 종목, 평가 시작 이후 종료), `listed_after_start`(첫 봉이 평가 시작 이후), `excluded_etf`, `universe_built_on`을 담고 머리말이 개수를 자동 기재한다. 종료 종목은 현재 상장 목록 안에서만 셀 수 있어 **하한**이다(이미 탈락한 종목은 목록에 없다). 또 "유니버스 선정에 빌드 시점(2025년 이후) 시가총액 순위가 쓰였다"는 look-ahead 경고를 항상 붙인다. 이전 manifest에는 이 필드가 없어 "미기록"으로 표시된다.
- **수정주가 (A5, 문서만)**: 가격은 Naver `siseJson`(`requestType=1`)의 **수정주가**로 받는다. 분할·무상증자 등 자본 변동이 과거 가격에 소급 반영되고, 배당은 이 요청에서 소급 조정 여부를 확인하지 못했다(미검증). 거래량은 가격과 같은 방식으로 수정됐는지 **확인하지 않았다**(미검증). 수준에 의존하는 규칙은 이 영향을 받는다: 호가단위 반올림과 2023-01-25 개편 전후 사다리, 정수 주 수(`floor(자본 × 비중 / 가격)`), 거래대금 하한(가격 × 거래량 20일 평균), 상·하한가 판정(전일 종가 기준 30% 폭). 수정 후 가격이 실제 체결가보다 낮으면 호가단위가 과소하고 정수 주·거래대금이 과대 평가된다. 비수정 원자료 확보는 사용자 결정 대기 중이라 이번 범위에서 하지 않았다.
- **고정 종목 목록 재생성 (K6)**: `--build-snapshot NAME --tickers-from <스냅샷 폴더|이름>`이 해당 manifest의 종목 목록·이름·`excluded_etf`로 `load_dataset(tickers=…)`를 호출한다(목록 API·ETF 필터 생략). 같은 목록이면 해시 입력(헤더·배열)이 같아 데이터가 같을 때 해시가 같다. 옵션이 없으면 기존처럼 현재 시총 상위를 쓴다.
- **테스트**: `test_nex16_fixes.py` — 이름 규칙·선정 크기 유지·`load_dataset` ETF 제외, 거래량 0 세션의 진입·청산 미체결 후 다음 세션 체결과 후보 제외, 10세션 결측 `delisted` 가격과 거래량 0 행의 카운터 미증가, 머리말 수치·경고·구 manifest, 같은 목록의 해시 동일.
