# 검증 체크리스트 (Validation 전용 기준서)

> 대상 스펙: `src/strategy/trend_following/trend_following.md` (현재 v05)
> 이 문서는 Validation이 모든 [V] 이슈에서 사용하는 기준이다. Dev와 Research는 수정할 수 없다. 변경은 사용자 승인 사항이다.
> 판정: 각 항목은 **통과 / 실패 / 해당 없음**으로 기록하고, 실패에는 재현 방법을 반드시 붙인다.

## A. Look-ahead 및 체결 규칙

| # | 항목 | 확인 방법 |
|---|---|---|
| A1 | t일 종가 기반 신호는 t+1 시가로만 체결된다 | 임의 20건 이벤트 추출 → 신호일/체결일/체결가를 원자료와 대조 |
| A2 | 투자자별 수급은 t일 장 마감 후에만 사용 가능하다: t일 수급을 쓴 결정은 t+1 시가 이후에만 체결된다(같은 날 시가·종가 체결 금지). 스펙 5장 "t일 수급 → t+1 시가" 규칙 그대로이며, 1일 시프트(t-1 수급으로 t 결정)는 요구하지 않는다 (2026-10-14 사용자 승인, NEX-30) | (1) t일 수급을 쓴 진입·청산 결정의 체결일이 모두 t+1 이상인지 원장으로 확인. (2) 수급 시계열을 1일 앞당겨(오염) 넣었을 때 성과가 유의하게 좋아지면 현행이 올바름. 현행과 오염 버전의 차이를 리포트 |
| A3 | 지표(MA, ATR, Donchian, 52주 고저)가 당일 이후 데이터를 쓰지 않는다 | 데이터를 t에서 절단 후 재계산한 값과 전체 계산값의 t 시점 값 비교 |
| A4 | 스코어링의 백분위 순위가 당일 유니버스 안에서만 계산된다 | 미래 구간 종목 추가/제거 시 과거 시점 점수 불변 확인 |
| A5 | 수정주가가 시점 일관성을 가진다 (분할/배당 반영이 신호 계산에 미래 정보를 주지 않음) | 분할 이벤트 종목 샘플 점검 |
| A6 | 상·하한가, 거래정지, 시가 미존재 시 체결 불가 처리 | 해당 일자 샘플의 체결 여부 확인 |

## B. 유니버스 및 생존편향

| # | 항목 | 확인 방법 |
|---|---|---|
| B1 | 유니버스가 시점 기준 구성인지, 현재 구성종목 소급인지 명시 | 소급이면 리포트 첫머리에 **편향 경고**와 영향 추정(상폐·탈락 종목 수) 기재 |
| B2 | 상장폐지/거래정지 종목 처리가 스펙과 일치 (`delist_after_missing`) | 해당 종목 샘플의 청산가 확인 |
| B3 | 유동성 필터가 시점별 20일 평균 거래대금으로 계산 | 필터 통과 종목 수의 시계열이 급변하지 않는지 확인 |

## C. 비용 및 운용 가정

| # | 항목 | 확인 방법 |
|---|---|---|
| C1 | 거래세가 연도별 표와 일치 (스펙 4-1) | 매도 체결 샘플의 세금 계산 재현 |
| C2 | 수수료, 슬리피지, 호가단위 반올림 적용 | 체결가와 호가단위 대조 |
| C3 | 비용 0 / 1× / 2× 세 시나리오 모두 실행 | 리포트에 표 포함 |
| C4 | 연초 1,000만 원 시작, 연말 종가 평가, 초과분 처리가 스펙과 일치 | 연도 경계 자산곡선 점검 |
| C5 | 단일 종목 상한 20%, 포지션 수 상한, 정수 주 매수 | 보유 내역 최대치 점검 |

## D. 벤치마크 및 공정 비교

| # | 항목 | 확인 방법 |
|---|---|---|
| D1 | BM1~BM4가 모두 같은 기간·같은 연초 리셋·같은 비용 기준으로 비교됨 | 비교표 확인 |
| D2 | BM1은 총수익(TR) 계열. 가격지수 사용 시 명시 | 데이터 출처 확인 |
| D3 | 초과수익, IR, 베타/알파, 업·다운 캡처, Calmar 보고 | 지표 존재 확인 |
| D4 | 개발 구간별 결과(2021-22 / 2023-24)를 분리 보고하고, 개발 실행의 데이터 종료일이 2024-12-31 이하임 | 표 확인 + 종료일 기계 검사 (스냅샷 manifest의 last_date와 리포트 데이터 기간 ≤ 2024-12-31) |
| D5 | 홀드아웃(2025) 결과는 스펙·파라미터 확정 후 1회만 열람하고, 합격/불합격 보고에만 쓰며 기준 조정에 쓰지 않음 | 열람 이력 1회 확인 (README 승인 게이트 3) |

## E. 강건성 및 과최적화

| # | 항목 | 기준 |
|---|---|---|
| E1 | 점검 요일(월~금) 변경 시 성과 분산 | 5개 요일 모두 실행. 최악 요일의 CAGR/MDD 보고 |
| E2 | 파라미터 주변값 (돌파 15/20/25, MA 등) | 주변값에서 성과가 급변하면 **실패** (급변 기준: Sharpe 변화 0.5 초과) |
| E3 | 비용 2× 에서도 BM 대비 우위가 유지되는지 | 유지되지 않으면 리포트 결론에 명시 |
| E4 | 수익이 소수 거래에 집중되었는지 | 상위 5% 거래 기여도 보고. 상위 5%를 제외한 성과도 함께 |
| E5 | 비교 횟수(시도한 변형 수)를 기록하고 다중검정 위험을 명시 | 시도 횟수를 리포트에 기재 |
| E6 | 파라미터가 결과를 본 뒤 바뀌었는지 | 이슈/커밋 이력과 스펙 버전 이력 대조 |

- E2 판정 방식 (2026-10-14 사용자 승인, NEX-10 안 A): E2는 **변형별로** 통과/실패를 기록한다. E2 실패 변형은 채택 후보에서 제외하며(판정 [J]에서 폐기), E2 실패만으로 감사 결론을 "보완 요청"으로 하지 않는다. 감사 결론은 구현·절차 항목(A~D, E1·E3~E6, F, G)으로 낸다. 사전 등록상 주변값 실험이 없는 변형은 "E2 해당 없음 — 주변값 강건성 미확인"으로 기록한다. 급변 기준(Sharpe 변화 0.5 초과)과 주변값 세트는 바꾸지 않는다.

## F. 홀드아웃

- 마지막 1년은 최종 채택 직전 **한 번만** 평가한다. 평가 전 사용자 승인을 받는다.
- 홀드아웃 결과가 개발 구간 대비 크게 나쁘면(Sharpe 50% 이상 하락 등) 채택하지 않고 원인을 기록한다.
- 홀드아웃 결과를 본 뒤 파라미터를 조정하면 그 구간은 소모된 것으로 보고 홀드아웃으로 다시 쓰지 않는다.

## H. 목표 지표 판정 (프로젝트 기준)

- Sharpe ≥ 1.5, MDD ≤ 15% (비용 1× 기준, 전 구간 및 구간별)
- 미달이어도 리포트는 통과/실패와 별개로 **수치와 한계**를 그대로 보고한다. 목표 달성 여부를 맞추기 위해 기준을 완화하지 않는다.
