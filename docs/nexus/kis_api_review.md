# 한국투자증권 Open API 활용 검토 (Nexus Trading)

- 작성일: 2026-11-04
- 대상: https://apiportal.koreainvestment.com/apiservice-summary 에 소개된 API 및 AI 도구
- 목적: Nexus Trading(한국 주식 추세추종, 모의투자까지)에 활용할 만한 API 선별

## 1. 요약

- 1차 목표(한국 주식 Donchian 추세추종 백테스트 + 모의투자)에는 **국내주식 시세·종목정보 API와 모의투자 주문 API**가 핵심이다.
- 해외주식, 채권, ELW, 퇴직연금은 현재 범위와 무관하다. 선물옵션은 대상 자산군이므로 후순위로 보류한다.
- 외환(FX) 현물 API는 목록에 없다. 해외선물의 통화선물로 대체 가능한지는 미확인이다.
- 포털의 백테스트 엔진은 **독립 구현 교차검증용**으로 검토할 가치가 있다. 트레이딩 MCP는 주문 기능이 있으므로 모의 키로 조회 위주로만 시작한다.
- 이번 검토에서 FAQ·서비스이용안내 페이지는 내용이 비어 있어(JS 렌더링) **호출 제한, 신청 조건, 과거 데이터 조회 기간은 확인하지 못했다.**

## 2. API 활용도 분류

### 2-1. 1순위: 바로 쓸 만한 API

| 영역 | API | Nexus에서의 용도 |
|---|---|---|
| OAuth | 접근토큰발급, 실시간 웹소켓 접속키 발급 | 모든 호출의 전제 |
| 국내주식 기본시세 | 국내주식기간별시세(일/주/월/년) | Donchian 20/10 돌파, MA20/50, 52주 Range 계산용 일봉. 현재 yfinance 기반 `get_historical_data()`의 대체·교차검증 소스 |
| 국내주식 업종/기타 | 국내휴장일조회, 국내업종 일자별지수 | 주간 리밸런싱 달력, KOSPI/KOSDAQ 벤치마크 |
| 국내주식 종목정보 | 상품기본조회, 주식기본조회, 예탁원정보(배당·분할·합병·액면교체 등) | 유니버스 정합성 관리, 액면분할·증자로 인한 가격 왜곡 점검 |
| 국내주식 주문/계좌 | 주식주문(현금), 정정취소, 잔고조회, 매수가능조회 | 모의투자 실행, 포지션·잔고 대조 |

### 2-2. 2순위: 전략 확장·검증에 도움이 되는 API

| 영역 | API | 용도 |
|---|---|---|
| 시세분석 | 종목별 투자자매매동향(일별), 외국인/기관 순매수, 공매도 일별추이, 신용잔고 일별추이, 프로그램매매추이 | 추세 신호 보조 필터, B안("추세+눌림") 점수의 추가 팩터 후보 |
| 순위분석 | 거래량순위, 시가총액 상위, 신고/신저근접종목, 이격도 순위, 체결강도 상위 | 유니버스 후보 스크리닝. 신고가 근접·이격도 순위는 기존 점수(MA20Div/MA50Div, 52주 Range)와 개념이 겹침 |
| 시세분석 | 종목조건검색 | HTS 조건식을 API로 불러와 후보 추출 |
| 실시간시세 | 실시간체결가·호가(KRX/통합/NXT), 실시간체결통보 | 모의투자 단계의 체결 모니터링. 일봉 기반 주간 전략이라 당장은 불필요 |

### 2-3. 3순위: 현재 범위 밖

- 해외주식, 장내채권, ELW, 퇴직연금: 현재 전략과 무관
- 국내선물옵션, 해외선물옵션: 대상 자산군이므로 한국 주식 전략이 안정화된 뒤 검토
- 외환: 현물 API 없음

## 3. 포털의 AI 도구

| 도구 | 내용 | 검토 의견 |
|---|---|---|
| 백테스트 엔진 | Lean 기반, Docker 필요. 전략 YAML 입력, 20개 이상 성과 지표(CAGR, MDD, 샤프 등), Grid Search 최적화, HTML 리포트 | Nexus는 자체 백테스트와 별도 검증 에이전트가 있으므로 **교차검증용 독립 엔진**으로 적합. 다만 입력이 YAML·프리셋(10종) 중심이라 Donchian + B안 점수 조합을 표현할 수 있는지는 확인 필요 |
| 전략 빌더 | 비주얼 방식 지표 기반 전략 설계, YAML 내보내기 | 백테스트 엔진 입력 생성용 |
| 트레이딩 MCP / 코딩도우미 MCP | AI 에이전트가 API를 탐색·호출하도록 연결 | 주문 기능이 포함될 수 있어 모의 키만 설정하고 조회 위주로 시작 |
| GitHub 샘플 (`koreainvestment/open-trading-api`) | 인증·호출 예제, 백테스터, 전략 빌더 | 어댑터 작성 시 참고 |

## 4. 설계 시 유의사항

1. **모의투자**: 백테스트 엔진의 설정 예시에 모의용 앱키·계좌와 별도 모의 도메인이 있어 API 수준에서 지원되는 것으로 보인다. 목표 범위가 모의투자까지이므로 모의 키만 설정하고, 코드에서도 실전 도메인으로 가는 경로를 차단한다.
2. **과거 데이터 깊이(미확인)**: 일봉 조회는 1회 조회 행 수가 제한적일 수 있고, 투자자매매동향·공매도 같은 일별 항목은 조회 가능 기간이 짧을 수 있다. 그 경우 2순위 팩터는 과거 백테스트에 쓸 수 없고 지금부터 매일 축적해야 한다. 각 API의 조회 기간은 API 가이드 문서에서 확인한다.
3. **호출 제한·토큰 갱신(미확인)**: 유니버스가 크면 종목별 순차 호출이 병목이 될 수 있다. 기존 `data/cache.py`를 활용한 캐시와 호출 속도 제어를 설계에 포함한다.
4. **검증의 독립성**: 구현 쪽은 yfinance, 검증 쪽은 KIS 시세로 데이터 소스를 분리하면 데이터 오류와 룩어헤드 문제를 함께 점검할 수 있다. 홀드아웃 데이터는 구현 에이전트가 접근하지 못하게 유지한다.
5. **인증 정보**: 앱키·시크릿은 로컬 PC 설정 파일에만 두고 git에 커밋하지 않는다. 클라우드 세션이나 에이전트 프롬프트에 붙여넣지 않는다.
6. **신청 조건**: API 사용에는 한국투자증권 계좌와 API 신청이 필요하다. 모의투자 신청 절차는 포털의 서비스 신청 페이지에서 확인한다.

## 5. 제안 진행 순서

1. KIS API 신청과 모의투자 키 발급
2. `data/` 계층에 KIS 일봉 어댑터 추가, 기존 yfinance 데이터와 종가·거래량 대조
3. 휴장일 API로 주간 리밸런싱 달력 구성
4. 모의투자 주문·잔고 API를 `strategy/trend_following` 실행부에 연결
5. 백테스트 엔진으로 Donchian 전략 YAML 표현 가능 여부 시험, 교차검증 용도 판단
6. 2순위 팩터(투자자 매매동향 등)는 조회 기간을 확인한 뒤 일별 축적 여부 결정

## 6. 미확인 사항 체크리스트

- [ ] API별 호출 제한(초당·일일)
- [ ] 일봉·분봉·투자자동향 등의 과거 조회 가능 기간과 1회 최대 행 수 (일봉은 1회 100행, 2021년 이전 미확인. 휴장일은 1회 24일, 2021년까지 확인. 분봉·투자자동향 미확인)
- [x] 수정주가(액면분할 보정) 제공 여부: `FID_ORG_ADJ_PRC` 0=수정, 1=원주가. 수정 시 거래량도 보정됨(카카오·에코프로비엠 실측, 스펙 9-20)
- [ ] 모의투자 신청 절차와 모의 환경의 제약(지원 종목·호가 등)
- [ ] 토큰 유효기간과 갱신 방식
- [ ] 백테스트 엔진에서 커스텀 전략(Donchian + 점수 조합) 지원 여부
- [ ] 외환 전략용 대체 API(해외선물 통화선물) 존재 여부

## 7. 구현 현황 (2026-11-04)

| 5장 단계 | 상태 | 내용 |
|---|---|---|
| 1. 모의투자 키 발급 | 사용자 작업 | 현재 키 폴더의 `kis_*` 파일은 실전 환경용으로 쓰이고, 모의 키로 확인된 파일은 없음 |
| 2. KIS 일봉 어댑터·대조 | 완료 | `data/raw_prices.py`, `data/price_crosscheck.py` |
| 3. 휴장일 기반 주간 달력 | 완료 | `data/krx_calendar.py`, `strategy/trend_following/schedule.py` |
| 4. 모의 주문·잔고 연결 | 미구현 | 스펙 9-19 J1에서 10개 변형이 모두 폐기되어 연결할 전략이 없고 모의 키도 없음 |
| 5. 백테스트 엔진 시험 | 미실시 | Docker 기반 외부 도구, 앱 코드 변경 대상 아님 |
| 6. 2순위 팩터 | 미실시 | 조회 기간 확인 후 결정 |

본문과 달라진 점: 한국 주식 일봉의 현재 소스는 yfinance가 아니라 Naver다. 대조 결과는 스펙 9-20에 있다.
