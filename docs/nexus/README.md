# Nexus Trading 운영 규칙 (단계 0)

> Paperclip 기반 에이전트 조직이 추세추종 알고리즘을 **사용자 입력 없이** 구현·검증하되, 구현과 검증을 분리하기 위한 공통 규칙.
> 에이전트별 지침: `agents/` · 검증 기준: `validation_checklist.md`
> 상태: 초안 v0 (2026-10-13). 단계 1 가동 후 실제 운영 결과로 개정한다.

## 1. 단일 진실 원천

| 대상 | 위치 | 수정 권한 |
|---|---|---|
| 전략 스펙 (버전 관리) | `src/strategy/trend_following/trend_following.md` 1~8장 | Research 초안 → CIO 검토 → **사용자 승인** 후 반영 |
| 구현 현황 | 같은 파일 9장 | Algorithm Dev |
| 코드 | `src/strategy/`, `tests/strategy/` | Algorithm Dev만 |
| 검증 기준 | `docs/nexus/validation_checklist.md` | CIO 제안 → 사용자 승인 (Dev 수정 불가) |
| 검증 리포트 | `reports/` | Validation만 |
| 에이전트 지침 | `docs/nexus/agents/*.AGENTS.md` | 사용자 (CIO 제안 가능) |

## 2. 이슈 유형과 흐름

접두사: `[R]` 연구 · `[S]` 스펙 변경 · `[D]` 구현 · `[V]` 검증 · `[J]` 판정

```
[R] Research  → 가설 카드 + 스펙 diff 초안
[S] CIO       → 사용자 승인 요청 → 승인 시 스펙 버전 확정
[D] Dev       → 구현 + 테스트(pytest, ruff 통과) → "구현 완료"
[V] Validation→ 감사 + 백테스트 + 리포트 → "검증 통과" 또는 "보완 요청"
[J] CIO       → 채택 / 보류 / 폐기 (검증 통과 없이 채택 불가)
```

- `보완 요청`은 Dev에게 새 [D] 이슈로 되돌아간다. 같은 원인으로 **3회** 반복되면 사용자에게 에스컬레이션한다.
- "구현 완료"와 "검증 통과"는 별개 상태다. 한 에이전트가 둘 다 선언할 수 없다.

## 3. 사용자 승인이 필요한 항목

1. 스펙 버전 변경 (v05 …) 및 파라미터 변경
2. 검증 기준(체크리스트) 변경
3. 홀드아웃 구간 결과 열람 (최종 1회)
4. 새 에이전트 채용, 월 예산 상향
5. `src/strategy/` 및 `tests/strategy/` 밖의 코드 변경 (기존 PyQt 앱, `data/` 계층 등)
6. 최종 채택 판정

## 4. 금지 사항 (모든 에이전트 공통)

- 실계좌·증권사 주문 API 연동, 자금 이동 (범위: 페이퍼 트레이딩까지)
- 백테스트 결과를 본 뒤 파라미터를 조정하는 행위 (별도 [R]→[S] 경로로만 가능)
- 비밀값(API 키, 토큰)을 문서·코드·코멘트에 기록
- 다른 역할의 산출물 직접 수정 (필요하면 이슈 코멘트로 요청)

## 5. 독립성 장치와 한계

- Validation은 **별도의 읽기 전용 클론**(`D:\Source Code\Portfolio Management Validation`)에서 테스트와 백테스트를 실행한다. 이 클론은 master 브랜치의 지정 커밋을 체크아웃해서 쓴다.
- 홀드아웃 구간(마지막 1년)의 데이터는 Validation 전용 경로(`D:\Source Code\Nexus Holdout`, Git 밖)에만 둔다. Dev의 작업 디렉터리에는 두지 않는다.
- 경로에 공백이 있으므로 스크립트와 명령에서는 항상 따옴표로 감싼다.
- **한계**: 위 접근 제한은 지침 문서만으로는 강제되지 않는다. OS 권한(읽기 전용 폴더 속성/별도 계정) 또는 Paperclip의 작업 디렉터리 설정으로 실제로 분리해야 한다. 이 설정은 단계 1 가동 전에 사용자가 확인한다.
- Validation도 같은 계열 모델이므로 맹점을 공유할 수 있다. 그래서 체크리스트의 정량 기준은 가능한 한 **코드(스크립트)로 기계 검사**한다.

## 5-1. 개발 구간과 홀드아웃 기간 (사용자 결정 2026-10-13: 홀드아웃 1년)

- 엔진이 달력 연도 단위로 연초 리셋(1,000만 원)하므로 홀드아웃은 달력 연도 단위로 잡는다.
- 개발 구간: 2021-01-01 ~ 2024-12-31 / **홀드아웃: 2025-01-01 ~ 2025-12-31** / 2026년은 진행 중이므로 개발에 쓰지 않고 포워드 관찰용으로 둔다.
- 영향: 스펙의 구간별 보고(2021-22, 2023-24, 2025-26) 중 2025-26 구간은 개발 중에는 평가하지 못한다. 이 변경은 CIO가 스펙 변경안([S])으로 올려 사용자 승인을 받는다.

## 6. 공통 문서 규칙

- 문서·이슈 코멘트·리포트는 **한국어**. 코드, 파일명, 기술 식별자는 영어.
- 이슈 종료 시 세 줄 요약: `무엇이 바뀌었나 / 근거 / 다음 단계`.
- 커밋 메시지는 이슈 번호(NEX-n)로 시작한다.
- 브랜치: 이슈마다 `nex-<번호>-<요약>`. master 병합은 Validation 통과 후에만.
