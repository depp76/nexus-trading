## 1. 전역 규칙

### 1.1 색 — 상승/하락·손익

**앱 전체에서 단 하나의 규칙을 쓴다. 파랑 = 이익/상승, 빨강 = 손실/하락**
(2026-09-22 사용자 지정 — 기존 한국 시장 관행(빨강=상승/파랑=하락)을 뒤집음).
"danger" 버튼/배지(삭제, 경고 배너, Sell 섹션 마커 등 가격 방향과 무관한 빨강)는
이 규칙과 분리된 `DANGER` 상수를 쓴다(`ui/colors.py`).

```python
# ui/colors.py — 모든 탭이 같은 곳에서 가져온다
PROFIT = "#3b6fc4"   # 이익, 상승
LOSS   = "#d1453b"   # 손실, 하락
FLAT   = "#75798c"   # 0, 미해당
DANGER = "#d1453b"   # 삭제/경고 등 가격 방향과 무관한 빨강 (PROFIT/LOSS와 별개)
```

당시 위반 사항(→ 현재 해결됨: 모든 셀이 `ui/colors.py`의 `fg_for()`/`heatmap_bg()`를 쓴다. 상태·판정 색은 8.3):

- `widgets.py` `_C_BG_BLUE_SEVERE` — 변화율 +30% 이상에 **파란** 배경 (상승=파랑)
- `widgets.py` `_populate_row` col 11/13 — High/Low Diff 양수에 `color_red` (상승=빨강)
- `history_table.py` `col_red`/`col_blue` — 이익=빨강 (관행과 일치)

### 1.2 색 농도 — 히트맵

- 모든 모멘텀/변화율 컬럼은 **하나의 공식**을 쓴다. 최대 농도 거리(`scale`)는 열 스펙에 둔다.
  → 현재: Chg ±5%, 3D~120D ±10%, MA Div 100 ±20, 금리 행 ±25bp(처음 제안한 "모두 ±10%"가 아님; 8.7).
- 농도는 `alpha = 0.04 + min(|v|/10, 1) × 0.20` (배경), 글자색은 항상 `PROFIT`/`LOSS` 원색.
- 임계값을 `if` 사다리로 하드코딩하지 않는다. 컬럼 스펙의 `scale` 값으로 분리한다.
- 범례를 표 하단에 상시 노출한다.

당시: `Div(20)`은 120/110/105/102/98/93, `Div(50)`은 130/110/107/103/98/90, 변화율은 ±30/±15/0 — 세 가지 스케일이 각각 코드에 박혀 있었다.
→ 현재 해결됨: `heatmap_bg(value, scale)` 하나, 범례는 Universe 푸터의 `HeatLegend`(8.7).

### 1.5 컬럼 폭

**고정 폭 금지.** 모든 컬럼은 `최소폭 + 비율`로 정의한다.

```
minmax(<최소폭>, <비율>fr)
```

- 최소폭은 그 컬럼에 들어갈 **가장 긴 값**의 폭(예: `1,849,000` → 86px).
- 최소폭 합계가 창 폭을 넘으면 가로 스크롤을 허용한다. 스크롤을 끈 채 강제로 욱여넣지 않는다.
- 가로 스크롤이 생기는 표는 식별 열(종목명·티커)을 좌측 고정한다.

당시 위반: `widgets.py` `MIN_W=38` + `ScrollBarAlwaysOff` → 값이 잘리는데 볼 방법이 없다. `assets_tab.py` `ResizeMode.Fixed` → 창을 넓혀도 그대로.
→ 현재 해결됨: Universe·Total Assets 모두 `ColSpec`(최소폭 + 비율), 가로 스크롤 `AsNeeded`, Universe는 이름 열 고정.

### 1.6 버튼

- **주 동작 1개**만 강조(accent 1px 아웃라인, 채움 없음). 나머지는 중립 아웃라인.
- 파괴적 동작(삭제)은 상시 노출하지 않는다 — 행 hover 또는 우클릭 메뉴. 확인 단계 필수.
- 버튼 색은 **의미**(주/보조/위험)를 나타낸다. 기능 종류별로 색을 배정하지 않는다.

당시 위반: `_BTN_BLUE`/`_BTN_ORANGE`/`_BTN_GREY`/`_BTN_INSIGHT` 4~5종의 채도 높은 fill이 툴바에 나열.
→ 현재 해결됨: `make_button()` + `#primary`/`#danger` 역할만(8.1). 삭제는 세 탭 모두 우클릭 메뉴 + Delete 키 + 확인 창.

### 1.7 상태 표기

- 상태(보유/관심/타깃/청산)는 **배지 + 행 좌측 3px 마커**로 표기한다.
- 셀 배경색을 상태 채널로 쓰지 않는다 — 지브라 줄무늬와 충돌하고 인쇄·색각이상에서 사라진다.
- 용어는 하나로 통일한다. 현재 헤더는 `Pf`, 버튼 라벨은 `On`/`Tg`/`-`, 배경은 노랑/하늘색으로 세 가지가 같은 상태를 가리킨다.
- (2026-09-29) 저장값 `On`/`Tg`의 표시 용어는 **Held / Target**(2026-10-15에 Port → Held; 저장값은 그대로). 행의 상태 버튼·행 컨텍스트 메뉴·툴바 상태 필터 버튼이 같은 단어를 쓴다. 툴바 상태 필터는 버튼 하나가 **빈 라벨(필터 없음) → Held → Target → 빈 라벨**로 순환하고, 라벨이 바뀌어도 크기는 고정(다른 필터 버튼과 동일 폭). 빈 상태만 unchecked. (2026-11-14) 필터 없음 상태의 라벨은 빈 칸 대신 **전체**: 전체 → 보유 → 관심 → 전체.
  (2026-11-16) 라벨을 **종목(전체) → 종목(보유) → 종목(관심)**(영어 Stocks (All/Held/Target))으로. 시장 토글 옆의 "전체"만으로는 "모든 시장"으로 읽혔다.
  같은 날 잠시 버튼 묶음 전체|보유|관심으로 바꿨다가 사용자 결정으로 순환 버튼 하나로 되돌렸다. 저장된 보기는 그대로 상태 값(`""`/`On`/`Tg`)을 저장한다.
- (2026-09-29) 행의 상태 표기는 배지가 아니라 **고정 크기(56×18) 버튼**이다. 빈 상태는 테두리만, Held는 연한 채움, Target은 진한 채움. 델리게이트가 그리고 `StockTable`이 클릭을 판정하므로 위젯은 없다. 클릭할 때마다 그 종목의 상태가 **빈 → Held → Target → 빈**으로 순환한다(더블클릭은 두 번 전진, MA 차트를 열지 않음). 컨텍스트 메뉴의 항목도 같은 순환을 한다.

### 1.8 표 상호작용

- 행 선택 + 키보드 탐색 허용(`SelectionBehavior.SelectRows`). 편집만 막는다.
  - 예외(2026-11-25, 사용자 지시): Trading Universe 표는 **마우스 클릭으로 행을 선택하지 않는다**
    (한 번 클릭에 행 색이 바뀌지 않게; `StockTable.selectionCommand`). 키보드 선택(화살표·Shift+화살표·Ctrl+A)과 Ctrl+C는 그대로.
- `Ctrl+C` — 선택 행 TSV 복사.
- `Enter` / 더블클릭 — 상세(MA 차트) 열기.
- 정렬 상태는 **데이터 갱신 후에도 유지**한다.

당시 위반: `widgets.py` `NoSelection` + `NoFocus` → 복사도 키보드 탐색도 불가.
→ 현재 해결됨: 행 선택·Ctrl+C·Enter가 Universe·History·Total Assets 표 모두에 있다(`install_table_keys`, 8.6).

### 1.9 데이터 갱신 정합성

**정렬 후 부분 갱신은 데이터 인덱스가 아니라 티커로 행을 찾아야 한다.**

```python
# 현재 (버그): data 인덱스를 뷰 행 번호로 그대로 사용
def update_changed_rows(self, data, changed_rows, highlights=None):
    for row in changed_rows:
        self._populate_row(row, data[row], highlights)
```

`setSortingEnabled(True)`이므로 사용자가 정렬한 뒤에는 data 인덱스 ≠ 화면 행. 60초 경량 갱신이 **다른 종목 행에 가격을 쓴다.**

→ `ticker → 현재 행` 매핑을 유지하거나, `QAbstractTableModel` + `QSortFilterProxyModel`로 전환해 정렬/필터와 데이터 갱신을 분리한다.
→ 현재 해결됨: `update_changed_rows`가 티커로 현재 행을 찾는다(`_ticker_to_row`). 위 코드는 당시의 버그 예시다.

### 2.1 구조

```

툴바:   [검색] [KOSPI|KOSDAQ|NASDAQ|S&P 500] [종목(전체) 순환] [필터][저장된 보기] ····· [종목 추가] [추세 점수] [새로고침]   (한 줄, 8.17)

        (종목 추가는 검색창 오른쪽 — 검색해 보고 없으면 추가. 전략 신호는 메뉴로 A0~C3 중 하나를 골라 상위·하위 10 고정, 전략 문서 9-29)

```

- (2026-11-14) **시장 토글**: KOSPI·KOSDAQ·NASDAQ(NASDAQ 100)·S&P500 네 개, 여러 개를 함께 켤 수 있고 최소 하나는 켜져 있어야 한다
  (사용자 지시, ALL 버튼 제거). **기본은 KOSPI + KOSDAQ**, 미국 두 시장은 꺼져 있다. 켜진 시장이 곧 새로고침이 받아 오는 시장
  (`AllDataFetchThread(markets=...)`, 시장별 상위 KOSPI 500 · KOSDAQ 700 (2026-11-26, 350·300에서 확대) · NASDAQ 150 150 · S&P500 510)이자 표에 보이는 시장이다.
  새로고침 뒤에 시장을 켜면 그 시장만(지수 제외) 받아 와 표에 합치고, 끄면 그 시장 행을 내린다(직접 추가한 종목은 남기고 숨김).
  새로고침 중에 켠 시장은 새로고침이 끝난 뒤 받는다. 선택은 `custom_settings.json`의 `markets`에 저장돼 다음 실행에도 유지된다.
  지수·금리·원자재 행은 시장 선택과 관계없이 늘 보인다. NASDAQ 100과 S&P500에 모두 있는 종목(AAPL 등)은 NASDAQ 100 행 하나로 두고
  다른 소속은 `also_in`에 적어 두어, NASDAQ을 끄고 S&P500이 켜져 있으면 그 행은 S&P500으로 옮겨 남는다. 직접 추가한 종목만 남은 시장은
  "받아 온 시장"으로 치지 않아 다시 켜면 그 시장 전체를 받는다. 한 시장을 받는 중에 다른 시장을 켜면 앞의 수집이 끝난 직후 받는다
  (2026-11-14 점검: 가짜·실제 QThread 시나리오 49개, 여기서 찾은 세 문제를 고침).
  저장된 보기는 시장 목록도 저장하고 적용 시 그 시장들로 바꾸며, 기본 보기·"전체 보기"는 시장을 건드리지 않는다(시장만 바꾼 상태는 필터로 치지 않음).
  추세 점수는 여전히 KR 종목만이다.
- (2026-11-15, 같은 날 정리) **미국 시장 이름**: 토글은 지수 구성 묶음이라 지수 이름 "NASDAQ 100"·"S&P 500"으로 표시(키는 그대로,
  버튼은 글자 폭에 맞춰 넓힘). 종목 추가와 거래 입력 창은 거래소 대신 "미국" 하나(저장 값 `US`) — 미국 조회는 거래소와 무관하다.
  예전에 NASDAQ·NYSE·AMEX·NASDAQ 100으로 저장된 거래·추가 종목은 그대로 읽히고 미국으로 처리된다(`is_us_market`).
  Strategy의 NASDAQ·NYSE는 거래소 기준 유니버스(지수·벤치마크 ETF도 거래소 기준)라 유지.
- (2026-11-15) **종목 추가 줄**: "추가할 시장" 라벨 삭제(콤보 툴팁이 필터와 별개임을 설명). 콤보는 KOSPI·KOSDAQ·NASDAQ·NYSE —
  미국 종목은 `fetch_single_stock`의 미국 경로(가격 원화 환산)로 받는다. NASDAQ·NYSE는 시장 토글이 없는 시장이라 그 시장으로 추가한 종목은

4. ~~마우스 세로선 + 차트 위 한 줄 읽기값~~ → 같은 날 8번으로 바뀜(세로선·읽기값 줄 삭제).
5. **X축 월 눈금**(데이터 범위 안의 매월 1일, "26.02").
6. 금액 **억 단위**(영어 화면은 "KRW 633.7M").
7. 총자산과 KOSPI 사이 음영: 앞서면 PROFIT, 뒤지면 LOSS(이 테마에서 PROFIT은 연한 파랑, LOSS는 연한 빨강), 투명도 0.12.
8. (같은 날 추가, 사용자 결정) **주별 마커**: 세 선의 매주 기록 위치에 점 — 총자산 속 찬 점, 총자산($) 속 빈 점, KOSPI 작은 점(선이 겹쳐도 구분).
   **마우스가 마커 위(중심에서 10px 안)에 있을 때만** 값 상자를 띄운다(사용자 결정: 세로선 불필요).
   세 선 중 어느 마커에 올려도 **그 주의 세 값을 모두** 보여 준다(같은 날 사용자 결정): 날짜 / 총자산 % · 억 / 총자산($) % · $ / KOSPI %,
   줄마다 계열 색, 그 주의 세 마커를 함께 키운다. 상자 테두리는 올린 마커의 계열 색, 차트 가운데 쪽으로 열려 밖으로 나가지 않는다.
   마커에서 벗어나면 사라진다. 차트 위 한 줄 읽기값과 세로선은 없앴다.

## 6. Qt 적용 — 목업과 실제 앱이 달라 보이는 이유

목업은 브라우저 렌더링이고 앱은 Qt 위젯입니다. 탭 코드를 고쳐도 **전역 스타일시트가 전부를 덮어쓰기 때문에** look & feel이 바뀌지 않습니다. 이 절을 **Phase 0**으로 먼저 처리해야 나머지 작업의 결과가 화면에 나타납니다.

→ 현재 구현됨: `ui/theme.py`의 `app_qss()`와 토큰. 아래 6.1은 당시 상태, 6.2의 코드는 당시 제안이며 실제 값은 `theme.py`가 기준이다
(예: 표 테두리는 `LINE_GROUP` 1px 직각, 셀 패딩 1px 3px — 8.2).

### 6.1·6.2 (옮김)

당시 전역 스타일시트 상태(6.1)와 Phase 0 테마 모듈 제안 코드(6.2)는 `docs/history/ui_archive_2026-09_10.md`로 옮겼다.
구현 결과가 기준이다: `src/ui/theme.py`(토큰·`app_qss()`·`app_palette()`), 8.16.

### 6.3 Qt에서 재현되지 않는 것과 대체 수단

| 목업의 표현 | Qt 대체 |
| --- | --- |
| `box-shadow` | 쓰지 않는다. 1px 경계선 + 배경 대비로 층을 만든다 (`QGraphicsDropShadowEffect`는 성능 비용이 크다) |
| 셀 단위 `border-radius` | 불가. 표 바깥 프레임에만 적용 |
| CSS grid / `minmax()` | 컬럼 스펙(§1.5)을 `resizeEvent`에서 픽셀로 계산해 `setColumnWidth` |
| 셀 안의 미니 바 / 레인지 바 / 스파크라인 | `QStyledItemDelegate.paint()` + `QPainter`. 셀 위젯(`setCellWidget`)을 행마다 심지 않는다 |
| 상태 배지(pill) | 델리게이트에서 `drawRoundedRect` + 텍스트. 또는 `QLabel` 하나를 셀 위젯으로 (행 수가 적을 때만) |
| `conic-gradient` 도넛 | matplotlib 또는 `QPainter.drawPie` |
| 행 hover 시 액션 노출 | `setMouseTracking(True)` + `entered` 시그널로 델리게이트가 아이콘을 그린다 |
| `text-wrap: pretty` | 없음. 긴 텍스트는 `QLabel.setWordWrap(True)` |
| 폰트 `Inter` / `IBM Plex Mono` | 맑은 고딕 Semilight 한 글꼴(숫자 포함; 1.3의 2026-09-19 결정. 당시 제안한 Consolas 숫자 글꼴은 폐기) |

### 6.4 폰트·DPI

- 목업은 CSS px, Qt는 pt(폰트) + px(QSS). `create_font(9)` ≈ 12px @96dpi. 명세의 px 값을 pt로 옮길 때 **× 0.75**.
- 고DPI에서 QSS의 px 값은 스케일되지 않으므로, 패딩·경계선은 작은 값(1–2px)으로 두고 크기는 폰트가 결정하게 합니다.
- `app.setStyle("Fusion")`을 권합니다. Windows 기본 스타일은 QSS 일부(특히 `QTabBar`, `QHeaderView`)를 네이티브 렌더링으로 무시합니다.

- **강조**: accent(보라)는 선택·체크·primary에만.
- **상태·판정**: `colors.OK`(초록, 양호·완료)와 `colors.WARN`(주황, 주의 — 빨강이 아니라 LOSS로 읽히지 않음),
  실패는 `DANGER`. tPER 저평가/고평가, 입력 오류, 상태 문구가 이 토큰을 쓴다(`DANGER_BG`/`DANGER_LINE` 포함).
- 그룹 헤더는 범주색을 쓰지 않는다: `GRP_BG` 바탕 + `TEXT_SUB` 라벨 + `LINE_GROUP` 선. 빨간 Sell·파란 Cumulative P/L
  헤더가 손실·이익처럼 읽히던 문제를 없앰. History 본문의 색 구분선도 제거(모든 선은 `#d0d0d0` 1px).
- 면책 고지는 정보이므로 `DANGER`가 아니라 `#muted`.
- `ui/theme.py`·`ui/colors.py` 밖에 hex 색을 쓰지 않는다.

### 8.7 갱신 실패 표시와 히트맵 범례 (2026-10-25)

- **갱신 실패**: `UniverseLightweightFetchThread.failed(reason)` — 예외가 나거나, 요청한 종목에 대해 시세를 하나도 받지 못하면
  (수집기는 네트워크 실패 시 예외 대신 빈 결과를 돌려준다) `finished_all` 직전에 보낸다. 일부라도 받으면 실패가 아니다.
  Universe 탭은 그 틱에서 표를 건드리지 않고, 마지막 정상 갱신 시각을 유지하고, 푸터에 `Auto-update failed: …`를 쓰고
  `refresh_failed(reason)`을 보낸다. 헤더 점은 마지막 실패가 마지막 성공보다 최근이면 **빨강(DANGER)**, 툴팁에 실패 시각과 사유.
  다음 정상 갱신에서 자동으로 초록으로 돌아온다. 상태 판정은 `ui.common.refresh_state()`(off / waiting / failed / late / ok).
- **히트맵 범례**(1.2 구현): Universe 푸터 오른쪽의 `HeatLegend` — `heatmap_bg()`로 직접 칠한 LOSS → 0 → PROFIT 막대와
  열별 최대 농도 기준. 1.2는 "모든 열 ±10% 공통"이었지만 실제 열 스펙은 Chg ±5%, 3D~120D ±10%, MA Div 100 ±20이므로
  범례 문구를 `COLUMNS`의 `scale` 값에서 만들어 셀과 어긋나지 않게 했다. 금리 행(±25bp)은 툴팁에 표기.

### 8.8 갱신 실패 범위 확대 (2026-10-25)

- **전체 새로고침**(`AllDataFetchThread.failed(reason, parts)`): 지수·KOSPI·KOSDAQ 중 예외가 나거나 0건인 부분을 알린다.
  Universe는 그 부분의 **이전 행을 유지**하고(새로고침 직전 스냅샷 `_prev_data`), 마지막 갱신 시각을 바꾸지 않고, 실패를 보고한다.
  이전에는 실패한 시장의 행이 표와 캐시에서 빠졌고, 네트워크가 끊긴 채 시작하면 표와 `universe_cache.json`이 비었다.
  `_save_universe_cache()`는 빈 목록으로 캐시를 덮어쓰지 않는다.
- **History 보유 종목 시세**(`RealtimePriceThread.failed`): 예외 또는 시세 0건이면 실패. 예외가 나면 스레드가 아무 신호 없이
  끝나던 것도 고침. 성공하면 `price_refresh_ok`.
  (2026-11-14, review_codex.md C12) 요청한 시장(국내 KIS / 미국 Yahoo) 중 하나라도 예외 또는 0건이면 실패이고,
  받은 시세는 반영하되 `prices_fetched(prices, complete=False)`라서 `price_refresh_ok`를 보내지 않는다. 전에는 국내만 받고
  미국이 실패해도 같은 요청의 성공 신호가 실패를 바로 지웠다. 한 시장 안에서 일부 종목만 빠진 것은 실패가 아니다.
- **헤더 점**: `ui.common.RefreshFailures`가 출처별(Trading Universe / Trading History) 실패를 들고 있고, **같은 출처의 다음 성공만**
  그 실패를 지운다. 그래서 History 시세 실패가 Universe 성공에 가려지지 않는다. 툴팁은 활성 실패를 모두 나열한다.

### 8.14 전략·BM 여러 개 선택 (2026-11-13)

    매매 내역(과 상세 팝업)에 보인다. 이미 선택된 변형을 기준으로 바꿔도 선택 순서는 그대로라 차트 색이 바뀌지 않는다.

  나머지는 각자 색의 선. readout은 기준 → 나머지 선택 순. "전체 표시"는 선택하지 않은 실행을 회색 가는 선으로 더한다.

  앞줄은 총자산 → **원금**(입력칸, 바로 오른쪽) → 총 손익(총자산 − 원금) → 총 손익(%), 구분선 뒤 매입 원가 · 예수금 · 출금.
  총자산 아래 줄에 "원금의 n.nn배", 툴팁에 세 항목 금액. 같은 날 값 아래 설명 문구("평가액 + 예수금 + 출금", "원금 대비", "누적" 등)는 지우고
  툴팁으로 옮겼다 — 값 아래에는 수치(원금의 n배, 예수금의 투자금 대비 %)만 남는다. 재입금(사용자 결정): 출금했던 돈을 계좌에 다시 넣으면 **출금(순출금)에서 빼고** 돈은 예수금으로 —
  총자산(평가액 + 예수금 + 순출금)이 입금일에 변하지 않아 Total Assets 주간 손익에 입금이 수익으로 잡히지 않는다.
  원금은 처음 넣은 3.5억 그대로이고, 출금 누계보다 많이 넣은 초과분만 원금에 더한다(순출금이 음수가 되지 않게).
  구분선 뒤(사용자 결정): 매입 원가 · **평가액**(보유 종목 현재가) · **평가 손익**(평가액 − 매입 원가) · 예수금 · 출금.
  평가 손익 %는 **운용 자금 = 예수금 + 매입 원가** 대비(매매는 예수금으로 하므로: 예수금 1억 중 5천만 원 매입, 평가 6천만 원 → +1천만 원 / 1억 = +10%).
  (같은 날 후속) 값 아래 줄은 모두 없앴다 — "원금의 n배", "운용 자금 대비 %"는 툴팁으로. 매입 원가 ~ 출금도 총자산과 같은 KPI 글자 크기,
  입력칸 높이는 숫자 라벨과 같게 해 한 줄에 맞춘다. 예수금은 직접 입력·KIS 조회 그대로(거래 기록으로 자동 증감하지 않음), 실현 손익 칸은 두지 않는다(매도 대금은 예수금 조회로 반영).
  입력칸 세 개(원금·예수금·출금)는 띠 안에서 숫자처럼 보여 편집할 수 있는지 몰랐다(사용자 보고) — 점선 밑줄, 마우스를 올리면 실선, 편집 중 accent 밑줄로 표시. 같은 값이던 "누적 자산" 칸은 없앴고, 출금을 뺀 평가액 + 예수금은 따로 보이지 않는다.

### 8.25 MA50 → MA60 전체 전환 (2026-11-18)

사용자 지시("ma50은 60으로 모두 변환"). 스펙 v07(10-13)로 전략의 추세선이 60일이 되어, 화면과 데이터에 남아 있던 50일 기준을 모두 60일로 바꿨다.

- **Universe 표**: `MA50 Div` 열 → **`MA60 Div`**(열 키 `ma60div`, 셀 값 = 가격 / 60일 이평 × 100, 60개 종가 미만이면 "-"). 범위 필터도 `MA60 Div`.
  데이터 키는 `changes["ma60_div"]`(`data.indicators.fetch_historical_changes`). 이전 캐시(`universe_cache.json`)의 50일 값은 의미가 달라 옮기지 않고,
  시작할 때의 새로고침에서 다시 계산될 때까지 "-"로 보인다.
- **저장된 보기**: `ma50div` 범위 필터는 읽을 때 `ma60div`로 옮긴다(`ui.universe_views.LEGACY_RANGE_KEYS` / `migrate_views`, 입력한 범위 값은 그대로).
  `custom_settings.json`에 옮긴 결과를 저장하고 상태 표시줄에 한 번 안내한다. 2026-11-18 현재 이 PC의 저장된 보기는 0개라 옮길 것이 없었다.
- **MA 차트 이격도 패널**: 이격도(50) → **이격도(60)** 선(`MA60_Div`, 색은 이전 그대로 `MA_DIV_LONG_COLOR`). 데이터 쪽 `_compute_indicators`는 MA50 대신
  MA60을 늘 계산한다(`windows`에 60이 있어도 한 번만).
- **그 밖**: AI 종목 리포트 입력 `ma60_divergence`, 이평 차트 로딩 문구. 전략 패키지의 필드 이름(`ma50_div`, `pct_ma50`)과 청산 사유 키 `ma50_exit`는
  화면에 보이지 않는 식별자라 호환을 위해 유지한다(스펙 10-8 별도 작업). 테스트 `tests/test_ma60_conversion.py`.

### 8.28 Trading History: KIS 조회 — 예수금과 체결 내역 (2026-11-18)

- **버튼**: '예수금 조회' → **'KIS 조회'**(같은 자리·같은 폭). 한 번에 KIS 계좌의 예수금, 보유 종목, 새 체결 내역을 가져온다(`threads.fetch_threads.KisAccountThread`).
  예수금은 이전처럼 예수금 칸에 바로 넣고 결과는 상태 표시줄. 사용자 결정: 거래 추가로 매매를 하나씩 적는 번거로움을 없애되, 체결 가져오기를 따로 두지 않고 예수금 조회에 합친다.
- **체결 조회**: KIS 주식일별주문체결조회(`inquire-daily-ccld`), 오늘부터 89일 안은 `TTTC0081R`, 그 앞은 `CTSC9215R`(`data.collectors.kis.fetch_kis_executions`).
  조회 시작일은 마지막으로 가져온 주문의 날짜, 처음이면 89일 전.
- **반영 규칙**(`ui/kis_sync.py` `plan_kis_import`, Qt 없음):
  - (2026-11-24 사용자 지시: 모든 매매는 독립된 거래, 평균 내지 않음) 같은 날·같은 종목·같은 방향이라도 **가격이 다르면 다른 행**, 같은 가격의 주문만 한 행.
    한 주문이 여러 가격에 체결되면 KIS가 주는 그 주문의 평균가로 한 행(주문별 체결가는 이 조회에 없다).
  - (2026-11-24) 금액은 **KIS가 실제로 정산한 수수료·세금 포함**: 매수 금액 = 가격×수량 + 수수료(+세금), 매도 금액 = 가격×수량 − 수수료 − 세금. 가격은 체결가 그대로.
    키움 기록(2026-11-24 PDF 대조)과 같은 방식. 비용은 기간별매매손익현황조회(`inquire-period-trade-profit`, `TTTC8715R`,
    `data.collectors.kis.fetch_kis_trade_costs`)의 (매매일, 종목)별 `fee`·`tl_tax`를 매수/매도로 나눠(한 행에 양쪽이 있으면 수수료는 금액 비율, 세금은 매도) 그날 행들에 금액 비율로 배분.
    KIS가 아직 비용을 내주지 않았거나 체결 금액보다 적게 내준 (날짜, 종목, 방향)은 **보류**: 가져온 것으로 표시하지 않고(pending), 같은 실행의 그 종목 이후 체결도 함께 보류해 다음 조회에 들어온다.
    응답 행이 체결 단위인지 (날짜, 종목) 단위인지는 실제 체결로 아직 확인 못 함(합산하므로 어느 쪽이든 같은 결과).
  - 매수 → 새 보유 행(시장은 KRX 상장 목록에서). 매도 → 그 종목의 보유 행을 **먼저 산 것부터** 청산, 일부만 팔린 행은 수동 일부 매도처럼 나눈다.
  - 보유보다 많은 매도는 통째로 건너뛰고 경고(가져온 것으로 표시하지 않아 다음 조회에 다시 나온다: 빠진 매수를 먼저 추가).
  - 주문은 "주문일:주문번호"로 구분하고, 주문별로 이미 가져온 누적 수량·금액을 `portfolio.db`의 `kis_imports`에 둔다. 다시 조회하거나 장중에 더 체결된 주문은 **차이만** 들어온다.
  - 반영 후 보유 수량을 KIS 잔고와 비교해 다르면 경고(체결이 있었거나 KIS가 보유한 종목만).
- **미리보기**(`ui/dialogs/kis_sync.py` `KisSyncDialog`): 날짜 · 구분 · 종목명 · 코드 · 수량 · 가격 · 금액 · 반영(새 보유 / 청산: 몇 일 매수분 몇 주 / 건너뜀)과 경고.
  '추가'를 눌러야 저장(거래와 `kis_imports`를 한 트랜잭션, `trade_db.apply_kis_import`) 후 DB에서 다시 읽는다. '취소'는 아무것도 저장하지 않는다. 새 체결도 경고도 없으면 창 없이 상태 표시줄에 "새 체결 없음".
- **자동 반영**(2026-11-24 사용자 지시: 확인 없이 자동): 자동 갱신(Auto Update)이 켜져 있으면 `MainWindow._on_global_auto_timer`가 매 분
  `TradingHistoryTab.auto_kis_sync_tick`을 부르고, 30분(`_KIS_AUTO_INTERVAL_S`)에 한 번 같은 조회를 `KisAccountThread(auto=True)`로 돌려 **미리보기 없이** 같은 규칙으로 저장한다.
  예수금 칸은 바꾸지 않는다(수동 'KIS 조회'만). 결과는 상태 표시줄("KIS 자동 반영: 체결 n건 · 보류 m건 · 경고 k건"), 경고는 `app.log`. 조회 중이거나 수동 미리보기가 열려 있으면 건너뛴다.
  보류된 체결은 다음 주기에 다시 확인한다. 첫 자동 조회는 자동 갱신을 켠 뒤 첫 틱(약 1분 뒤).
- **제한**: 국내 주식만(해외 체결은 다른 API). 보유 종목은 첫 페이지(50종목)까지. 같은 매매를 '거래 추가'로도 적으면 두 번 들어가니 KIS 계좌 매매는 KIS 조회로만 넣는다.
  2026-11-18 현재 이 계좌는 최근 3개월 체결이 없어 실제 체결로는 아직 확인하지 못했다(조회 호출과 빈 응답은 확인, 반영 로직은 테스트 `tests/test_kis_sync.py`).

  같은 기간을 보여 주는 차트(왼쪽)와 표(오른쪽)가 한 카드에 있어 이 전환이 둘을 함께 바꾼다는 것이 보인다.
- **차트**(matplotlib): 분기 모드는 최근 5년 분기 매출 막대 + 영업이익률 선(오른쪽 축, `ACCENT`). 4분기(계산값)는 빗금, 영업적자 분기는 `LOSS`색.
  연간 모드는 연도 막대(진행 중인 해는 누계, 빗금) + 연간 이익률.
- **실적 표**: 행 = 항목(매출 · YoY · 영업이익 · YoY · 이익률 · 지배순이익 · YoY · 비고 · 접수일), 열 = 기간
  (왼쪽이 과거, 차트·사업부별 표와 같은 방향). 열면 오른쪽 끝(최신)까지 스크롤된 상태이고, 사용자가 스크롤하기 전까지 열 폭이 정해져도 끝에 붙어 있다.
  YoY는 파랑/빨강, 비고는 흑자전환/적자전환/적자지속(전년 동기 기준) · ⓡ 정정. 항목 이름은 세로 머리글이라 좌우 스크롤해도 왼쪽에 고정되고,
  좌우 스크롤바는 그 고정 열 오른쪽(기간 열 아래)부터 시작한다(Qt 기본 바는 끄고 표 아래 별도 `QScrollBar`를 동기화).
  변천(모두 2026-11-26 사용자 지시): 처음 구현은 행 = 기간 최신순 → 행/열 전환(최신이 왼쪽) → 과거가 왼쪽 + 영업이익·순이익 YoY 추가.
