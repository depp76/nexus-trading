# UI 디자인 검토 및 제안 — 2026-11-14

상태: 디자인 제안 및 후속 검토 문서. 최신 작업 트리에는 Soft Slate 관련 변경과 `docs/ui.md` 8.16이 있으므로 구현 상태는 해당 명세와 코드를 기준으로 확인한다. 아래 6장은 버튼·배치·크기의 후속 개선 제안이며, 이번 문서 업데이트에서는 제품 소스를 변경하지 않았다.

## 1. 권장 방향

**Soft Slate: 밝기를 높인 청회색 다크 화면 + 밝은 텍스트 + 절제된 라벤더 강조.**
표의 정보 밀도를 유지하면서 필터, 실행 동작, 분석 결과의 위계를 분명하게 한다. 주요 화면에 카드를 추가하기보다 중복 경계선과 반복 정보를 줄인다.

최신 시안은 사용자 피드백에 따라 초기 Institutional Light 및 짙은 다크안을 대체한다. 검정 텍스트가 어두운 배경에 남지 않도록 명시적으로 글자색을 지정하고, 제목은 키우고 본문·표·KPI 숫자는 줄였다. Light 전환은 보조 선택으로 유지하는 제안이다.

최신 시안: [Soft Slate — 제목·본문 크기 조정](C:/Users/jongg/.codex/visualizations/2026/11/13/01a1d702-deee-7350-92ca-002cefa7295e/slate-typography.html). 이 파일은 Codex 대화용 HTML 시안이며 실제 앱 실행 화면이 아니다. 네 탭 전환과 매매 내역 팝업으로 외형을 확인할 수 있으며, 데이터는 예시다. 축약된 시안의 열·컨트롤 개수를 실제 기능 삭제 요구로 해석하지 않는다.

검토 근거: `src/main.py`, `src/ui/theme.py`, `colors.py`, 네 탭의 레이아웃 코드, MA/매매 내역 팝업 코드, `docs/ui.md` 8장, 기존 네 탭의 렌더링 이미지. 기존 이미지는 테스트 데이터·빈 상태를 포함하며 최신 코드는 별도로 대조했다. 모든 실제 운영 상태와 DPI를 실행 검증한 리뷰는 아니다.

## 3. 현재 문제와 공통 개선

1. **약한 행동 위계:** primary도 보조 버튼과 유사한 흰색 외곽선이다. 탭당 주요 동작 하나만 진한 보라색 채움으로 바꾸고 나머지는 중립 외곽선으로 유지한다.
2. **텍스트보다 강한 격자:** 작은 보조 글씨와 연한 색에 비해 모든 셀의 회색 선이 강하다. 가로선은 연하게, 세로선은 열 그룹 경계 중심으로 줄인다. 숫자 우측 정렬과 그룹 헤더는 유지한다.
3. **툴바 과밀:** 검색·필터·추가·분석 동작이 긴 한 줄에 섞인다. 주된 필터는 상시 노출하고 드문 동작은 펼침 영역으로 정리한다. 좁아지면 의미 단위로 두 줄에 배치한다.
4. **입력 외형 불일치:** 전역 입력 QSS가 QLineEdit/QComboBox/QDateEdit 중심이라 숫자 입력과 차이가 난다. SpinBox/DoubleSpinBox의 높이·테두리·포커스도 통일한다.
5. **빈 상태:** Total Assets의 빈 그래프는 0~1 축을 표시한다. 축 대신 “주간 기록을 추가하면 추이가 표시됩니다” 안내를 쓴다. 미조회·데이터 없음·실패를 다른 문구로 표시한다.
6. **반복 정보:** Strategy의 목표 판정은 KPI와 큰 우측 패널에 중복된다. KPI 배지는 유지하고 점검 패널은 한 줄 요약 + 펼침 상세로 축소한다. 미실행 검증 안내는 상세에도 반드시 유지한다.

어두운 표·패널에 기본 검정 글씨를 상속하지 않는다. 본문, 직접 그리는 표 셀, 입력값, 선택된 행, 메뉴, 콤보박스 목록, 팝업 및 차트의 축·눈금·범례·툴팁까지 테마별 전경색을 지정한다. 비활성 상태도 검정으로 처리하지 않고 별도의 읽을 수 있는 회색을 사용한다.

본문·보조 글씨·손익색은 본문 면과 선택 배경 각각에 대해 계산상 대비율 4.5:1 이상이다. 이는 해당 조합의 계산 결과이며 모든 실제 UI 상태를 실행 검증했다는 의미는 아니다. 히트맵이 합성된 배경, 비활성 상태, 작은 글씨, 포커스와 상태 배지는 별도 검수한다.

MA 계열은 다크 배경에서 구분되는 명도·선 패턴·끝점 라벨을 함께 사용한다. 차트 계열색은 수익 판정색과 별도 범례로 설명한다. 다중 전략의 색은 선택 순서 변경에도 동일 ID에 고정하는 개선을 제안한다.

| 역할 | 최신 HTML 시안 | 비고 |

| 본문·표·입력값·일반 버튼 | 12px | 정보 밀도 유지 |
| KPI 숫자 | 18px | 이전 시안 21px에서 축소 |
| KPI 라벨·설명·푸터 | 11px | 보조 정보 |

위 값은 **HTML 시안의 CSS px 기준**이다. 실제 PyQt 앱에서는 기존 Malgun Gothic Semilight와 `create_font()` / `FONT_*` 체계를 유지하고 pt 및 Windows 배율에 맞춰 대응시킨다. CSS px 숫자를 Qt pt 값에 그대로 대입하지 않는다. 제목/본문의 크기 위계는 유지하되 100/125/150% 배율에서 실측 후 토큰 값을 확정한다. 시안은 500px 이하에서 제목 20px·부제 및 탭 14px, 터치 환경에서는 입력 16px·버튼 최소 44px로 조정한다. 이 웹 시안의 좁은 화면 규칙을 데스크톱 앱에 그대로 강제하지 않는다.

앱 기본 행 높이 24px, Universe 28px, 버튼 28px는 유지한다. 일반 글씨 대비 4.5:1, 중요한 비문자 표시 3:1을 검수 목표로 두되 얇은 실제 글꼴의 가독성도 별도 확인한다.

## 4. 화면별 배치

### Trading Universe

- 검색 → 시장 → 보유/관심/필터 → 저장된 보기 순서. 오른쪽에 종목 추가, 추세 점수, 새로고침.
- 원래 가격·밸류에이션·52W·기간 수익률 열을 우선한다. 열 그룹 이름과 단위로 읽기 순서를 만든다.
- Score 열 및 상시 우측 상세 패널은 복원하지 않는다. Trend Score 상세는 MA 팝업에 유지한다.
- 선택 행은 채도를 낮춘 보라 배경(`#514B69`)과 좌측 표시를 사용하되 손익색과 히트맵 값을 덮지 않는다.
- 기본/가격·추세/밸류에이션 등의 저장된 보기를 활용하되 기존 모든 열을 볼 수 있는 보기를 보존한다.

### Trading History

- 필터·기간·상태별/월별 묶음을 왼쪽에 모으고 거래 추가를 오른쪽 끝에 둔다.
- KPI 8개를 같은 강도로 강조하지 않는다. 총자산·총손익·수익률을 우선하고 원금·원가·입출금은 같은 띠의 보조 정보 또는 펼침 영역으로 제공한다. 수치와 접근 경로는 유지한다.
- Buy/Sell/Position/Past의 그룹 구조를 유지하면서 그룹 사이만 구분선을 강조한다.
- 거래일 가운데, 가격·수량·금액 오른쪽 정렬. 종목명 및 티커는 상세 창에서도 동일하게 표시한다.

### Total Assets

- 별도 KPI 띠는 추가하지 않는다(기존 사용자 결정 유지).
- 상단 통화·환율·상세 그래프·내보내기 → 기존 현재 총자산/주간 손익과 기록 입력 → 추이 차트 → 주간 표 순서를 권장한다.
- 현재 200px 고정 차트는 사용자가 표와의 높이 비중을 조절할 수 있게 한다. 초기에는 표를 충분히 보여준다.
- 차트와 표에 동일 통화 및 기준 기간을 표시한다. 실시간 추정 자산과 저장된 주간 기록을 명시적으로 구분한다.

### Strategy

- 실행 폼은 기본으로 계속 열어 둔다. 1행에 기간·시장·목표 Sharpe, 2행에 유니버스·유동성·최대 보유·점검 요일·비용·변형 및 옵션을 의미 단위로 배치한다. 창 폭에 맞춰 줄바꿈하며 1행 강제 축소는 하지 않는다.
- 리서치 실행을 우측 끝의 유일한 채움 버튼으로 한다. 저장·중지·설정 접기는 보조 동작이다.
- 결과 위에 **“표시 중인 결과: 실제 데이터 기간 / 시장 / 비용 / 실행 당시 목표 Sharpe”**를 표시한다. 다음 실행 폼을 바꿨을 때 기존 결과가 바뀐 것으로 오해하지 않게 한다.
- 비교 대상은 체크박스 다중 선택, 상세 기준은 별도 단일 선택으로 분리하는 안을 권장한다. “상세 기준 A1”을 KPI와 매매 내역에 명시한다.
- KPI 6개와 목표 배지는 유지하되 카드 높이·설명 간격을 줄인다. 긴 지표 설명은 툴팁을 병행한다.
- NAV와 drawdown 차트는 가로 전체 사용. 목표 점검은 짧은 요약과 펼침 상세. 차트/결과 표는 높이를 조절할 수 있게 한다.
- 목표 Sharpe 기본 1.0, 실행 당시 기준 적용, MDD 기준 15%와 계산 의미는 유지한다. 목표 입력은 전략 수익률을 강제로 만드는 최적화 옵션이 아니다.
- 모든 결과 하위 탭, 경고와 연구 한계 문구는 유지한다.

### 팝업 및 보조 화면

- MA: 종목명·티커·시장·가격·기준일 → 기간/계열 선택 → 차트. 추세 점수·수급은 폭 조절 가능한 상세 영역, 좁은 창에서는 접기/탭으로 제공한다.
- 매매 내역: 본문과 팝업의 동일한 15열·검색·필터·정렬 유지. 날짜 가운데, 가격 오른쪽. 전체 열 폭으로 열되 화면 가용 폭 이내로 제한한다. 좁은 화면에서는 폰트를 축소하거나 열을 삭제하기보다 가로 스크롤을 허용한다.
- 편집/변형 선택: 라벨과 입력의 시작선을 맞추고 확인/취소 위치를 통일한다. 오류는 해당 필드 옆에 표시한다.
- 보고서/종목 상세: 본문 대비와 단위·기준일을 통일하고 기존 크기 조절·복사 기능을 유지한다.

## 5. 적용 순서와 완료 기준

1. **공통 외형:** Soft Slate 팔레트, 모든 텍스트의 전경색, 제목/본문 글자 크기, 버튼 위계, 숫자 입력, 표 선, 빈 상태. Qt 테마뿐 아니라 직접 그리는 셀과 matplotlib 차트도 함께 적용한다. docs/ui.md 8.1/8.2/8.3/8.5의 버튼·격자·색상·글꼴 규칙 변경을 함께 명시해야 한다.
2. **Strategy:** 결과 기준 표시, 비교/상세 선택 분리, 목표 패널 축소, 차트/표 비중 조절. 8.10/8.14 개정 대상이다.
3. **나머지 탭 및 팝업:** 툴바 정리, History KPI 위계, Assets 입력 순서, 팝업 일관성. Assets KPI 금지와 Universe Score 열 제거는 유지한다.

구현 시 단계마다 pytest 및 ruff를 통과하고 별도로 1366×768, 1920×1080 및 Windows 100/125/150% 배율에서 확인한다. 긴 종목명, 4개 시장, 다중 전략/BM, 빈 데이터, 갱신 실패, 긴 매매 내역을 검수한다. 모든 기존 열과 기능 접근 경로, 키보드 탐색, 정렬·복사, 다이얼로그 크기 조절을 확인한다. 전략 계산·DB·데이터 수집은 변경 대상이 아니다.

## 6. 전체 UI 버튼 순서·배치·크기 후속 검토

검토일: 2026-11-14. `main.py`, 네 탭, `common.py`, `dialogs/`의 버튼 구성·레이아웃·크기 지정 코드를 확인했다. 아래는 코드 구조에 근거한 개선안이며 실제 화면에서 모든 폭과 DPI의 잘림을 재현한 결과는 아니다. 4장의 방향을 구체화하며, 상충하는 배치 제안은 이 장을 우선한다. 이미 반영된 색상·Assets 입력 순서 개선을 미구현으로 취급하지 않는다.

### 6.1 공통 순서와 크기 규칙

- **필터 → 보기 방식 → 분석/보조 동작 → 주요 동작** 순으로 읽히게 한다. 한 작업에 필요한 입력과 버튼은 붙이고, 관련 없는 작업 사이에는 여백을 둔다.
- 각 탭의 주요 동작은 기존대로 오른쪽 끝: 새로고침 / 거래 추가 / 기록 추가 / 리서치 실행. 주요 동작만 채움 버튼이고, 조회·저장·닫기는 중립 버튼이다.
- 편집 팝업은 하단 오른쪽 **취소 → 저장**, 선택 팝업은 **취소 → 확인**으로 통일한다. 조회 팝업은 **내보내기(있을 때) → 닫기**. 삭제는 기존 우클릭·Delete·확인 방식 유지.
- 버튼의 텍스트는 현재 수행할 동작을 표현한다. 접힌 설정에는 `설정 펼치기`, 펼친 설정에는 `설정 접기`. 버튼 폭은 두 문구 중 긴 것에 맞춰 전환 시 흔들리지 않게 한다.
- 실행 중에는 버튼 위치를 유지한다. 실행 비활성·중지 활성·진행 상태 표시를 사용하고, 종료하면 같은 자리에서 복귀한다. 색상만으로 실행 가능 여부를 전달하지 않는다.
- 버튼과 한 줄 입력은 **28 논리 px**를 기준으로 맞춘다. 주요 버튼도 높이는 같고 색상으로 위계를 만든다. OS 배율은 Qt가 처리하도록 하며 물리 px를 직접 고정하지 않는다.
- 일반 버튼 폭은 `문구 실측 폭 + 좌우 여백 각 10~12px`를 기준으로 한다. 고정 폭은 같은 그룹의 세그먼트·문구가 바뀌는 버튼에 한정하고, 가장 긴 라벨과 스타일의 최소 폭을 반영한다.
- 같은 작업 안 간격 6~8px, 작업 그룹 사이 12~16px, 탭 바깥 여백은 기존 12×10px를 기본으로 한다. 간격 때문에 표가 좁아지면 먼저 줄바꿈한다.
- 검색창 권장 초기 폭 180~220px, 날짜 입력 120~140px, 시장 선택 100~120px, 금액 입력 140~180px, 작은 숫자 입력 72~96px. 이는 **초기 폭 후보**이며 문자열·화살표·통화 단위를 실측한 최소 폭보다 작게 강제하지 않는다.
- 날짜 가운데, 금액·수량 오른쪽, 이름·코드 왼쪽 정렬을 유지한다. 전체 숫자를 보려면 툴팁을 열어야 하는 금액 입력란은 피한다.

### 6.4 공간 배분과 좁은 화면 처리

- 기준은 모니터 해상도보다 **실제 콘텐츠 가용 폭**이다. 초기 검수 구간은 1440 이상 / 1100~1439 / 1100 미만 논리 px로 나누되, 분기점은 위젯 `sizeHint` 합과 글꼴 실측으로 확정한다.
- 넓은 창에서도 모든 버튼을 한 줄에 몰지 않는다. 좁아지면 검색·시장, 기간, 추가 입력 같은 의미 단위로 줄을 나눈다. 글자를 줄이거나 주요 동작을 화면 밖으로 밀어내지 않는다.
- 표 중심 탭은 툴바 높이가 내용에 필요한 만큼만 차지하고 표가 남는 높이를 사용한다. History KPI는 한 띠를 기본으로 하되 줄바꿈 시 표의 최소 사용 공간을 확보한다.
- Strategy는 설정 폼의 기존 FlowLayout을 유지하면서 결과 저장 동작을 분리한다. 차트와 결과 표는 세로 splitter를 사용하고 초기 높이 비중은 약 55:45 후보로 시작한다. 사용자의 마지막 비율을 기억하되 각 영역의 최소 가용 높이를 보장한다.
- Total Assets는 이미 반영된 입력 → 차트 → 표 순서를 유지한다. 차트 200px는 초기 높이 후보이며 고정하지 않고 표와 비율 조절 가능하게 한다. KPI 띠는 추가하지 않는다.
- 모든 화면에 동일한 제목/본문 위계를 적용한다. 공간 부족을 이유로 3장의 본문·입력 글씨를 더 줄이지 않는다. 긴 종목명은 열 확장/툴팁을 병행하고 핵심 입력값은 잘리지 않게 한다.

### 6.5 실행 상태와 키보드 검수

- Tab 이동은 화면의 읽기 순서와 일치. 검색 입력 Enter는 검색, 표 Enter는 기존 상세 보기, 팝업 Esc는 기존 취소/닫기 규칙을 따른다. 저장 중 닫기 차단 등 기존 보호 동작은 유지한다.
- 폼의 숫자·날짜 입력에서 Enter를 누르는 것만으로 리서치 실행이나 저장이 우발적으로 시작되지 않게 한다. 기본 버튼 정책은 팝업 종류별로 명시한다.
- 리서치 실행 전에는 저장 불가 사유, 실행 중에는 진행 상태, 완료 후에는 표시 중인 결과의 기준을 제공한다. 기존 결과를 저장할 수 있다면 어떤 결과인지 명시하고 새 실행 설정과 혼동하지 않게 한다.
- 테마 검수는 일반/hover/pressed/checked/focus/disabled와 입력 오류까지 포함한다. 비활성 버튼도 라벨을 읽을 수 있어야 하며, 포커스 표시와 선택 상태는 구별한다.
